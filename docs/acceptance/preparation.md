# Приёмка MVP на ГУ: подготовка

Это инструкция для владельца. Она готовит всё до выезда к автомобилю.
Сами проверки прогона 3 описаны в [test-plan-run3.md](test-plan-run3.md). Форма результатов — в [report-template-run3.md](report-template-run3.md).
Тикет приёмки: [#89](https://github.com/krasotinpa/super-radio-android/issues/89).
Это материалы для **повторного** прогона. Первый прогон — [report-run1.md](report-run1.md). Что повторять — [retest-plan-run3.md](retest-plan-run3.md).

## Итог

1. APK собирает агент из `main` перед выездом. Версия, коммит и SHA-256 записываются в шапку отчёта (шаг 5). Старый APK 0.1.0 (коммит `1164918`) не используй: в нём щелчки.
2. Нужны: SSD (exFAT или FAT32) для APK и копирования Журнала, переходник OTG, Модуль с антенной, телефон для фото и видео.
3. Время: около 1,5 часа, из них 30 минут — непрерывный приём.
4. Автомобиль стоит. Громкость ГУ малая. Это правило безопасности из AGENTS.md.

## Что взять с собой

| № | Предмет | Зачем |
|---|---|---|
| 1 | SSD с файловой системой exFAT или FAT32 | Перенос APK на ГУ и вывод Журнала с ГУ |
| 2 | Переходник OTG (USB-C) | SSD и Модуль подключаются к одному разъёму ГУ |
| 3 | Модуль и антенна | Приём радио |
| 4 | Телефон | Фото экрана ГУ, короткие видео |
| 5 | Распечатанный [test-plan.md](test-plan.md) или второй экран | Чек-лист шагов |
| 6 | Часы или таймер на телефоне | 30 минут приёма |

AM-станции в регионе нет. Слышимость AM помечена `not tested` заранее. Это допустимо по requirements.md.
Нужно приложение навигатора на ГУ. Для проверки фокуса нужен ещё один плеер (например, FMPLAY, как в прошлых проверках).

## Шаг 1. Получить APK

Файлы лежат на компьютере в WSL-дистрибутиве `Ubuntu`, в папке `raw/acceptance/` репозитория. Новый APK агент кладёт в `raw/acceptance/run3/`.

```text
Windows-путь:  \\wsl$\Ubuntu\home\user\sources\super-radio-android\raw\acceptance\run3\
Файлы:         heterodyne-fm-<versionName>-debug.apk
               SHA256SUMS.txt
```

1. Открой этот путь в проводнике Windows.
2. Скопируй оба файла в **корень SSD**.
3. Безопасно извлеки SSD.

Gradle создаёт `app/build/outputs/apk/debug/app-debug.apk`. При подготовке агент копирует его под именем `heterodyne-fm-<versionName>-debug.apk`.
Например: `heterodyne-fm-0.1.0+11a88f6-debug.apk`. Gradle сам файл не переименовывает.

`versionName` имеет формат `0.1.0+<SHA>[-dirty]`; SHA содержит первые семь символов коммита.
Суффикс `-dirty` означает изменения отслеживаемых файлов, включая staged-изменения. Неотслеживаемые файлы не учитываются; новые исходники добавляют в Git до сборки.
Без Git-контекста или при ошибке Git версия равна `0.1.0+unknown`; сборка выводит предупреждение с причиной.
Для вычисления версии нужны Python 3.12 и Git. Каждый вызов Git ограничен пятью секундами.

Новый коммит меняет версию, BuildConfig и манифест. Это нужно для идентификации установленного APK.
Метка `-dirty` не сохраняет изменения и не гарантирует воспроизводимость сборки. Для приёмки используй чистый checkout конкретного коммита.
Полную версию и SHA-256 конкретного APK запиши в отчёт. Сам APK сохрани для повторной установки.

Контрольную сумму APK агент пишет в `SHA256SUMS.txt` и в шапку отчёта.

Если хочешь проверить SSD: в PowerShell выполни `Get-FileHash E:\heterodyne-fm-<versionName>-debug.apk -Algorithm SHA256`. Замени `E:` на букву SSD. Результат должен совпасть с `SHA256SUMS.txt`.

## Шаг 2. Подготовить отчёт

1. Создай на телефоне или в чате заметку и скопируй в неё таблицу из [report-template.md](report-template.md).
2. На каждом шаге плана записывай статус и комментарий.
3. Фото называй номером шага: `T05-1.jpg`, `T05-2.jpg`. Если телефон не даёт задать имя, снимай по порядку и пиши в заметке: «фото 17 = шаг T05».

## Шаг 3. Что нужно знать про приложение

1. Приложение называется **Heterodyne FM**. Установка идёт из файла, как у прошлого Super Radio Probe.
2. Приложение не запускается само. Запускай его вручную из списка приложений.
3. Звук включается только кнопкой «Старт» (одна кнопка «Старт / Стоп») или выбором Станции.
4. Приложение создаёт Журнал само. Журнал переживает перезагрузку ГУ. Вручную его включать не нужно.
   Экспорт: «Стоянка» → «Диагностика» → «Экспорт Журнала». Файл ложится в `Download` внутренней памяти ГУ. SSD и отключение Модуля для экспорта не нужны.
5. Экран движения называется «Эфир». Режим стоянки открывается кнопкой «Стоянка» вверху справа.
6. Установка поверх прошлой версии работает, если подпись та же. При ошибке «Приложение не установлено» удали старое Heterodyne FM и установи снова.

## Шаг 4. Правила безопасности

1. Автомобиль стоит. Ручной тормоз включён.
2. Громкость ГУ малая. При громком звуке или треске нажми «Стоп».
3. Приложение шлёт Модулю только команды из списка `command-catalog.md`. Других команд в нём нет.
4. Не нажимай в режиме разработчика кнопки, которых не просит план.
5. Не делай сброс, обновление прошивки и другие действия с Модулем вне плана.
6. Модуль и SSD используют **один разъём**. Не подключай оба одновременно.

## Шаг 5. Что делает агент до выезда

1. Проверил, что `main` содержит тикеты прогона 3: #171, #177–#181, #193–#196, #200–#203, #205–#207, #209, #219, #158, #230.
2. Собрал APK: `./gradlew test lint assembleDebug` завершился с кодом 0.
3. Записал SHA-256, коммит и версию (`versionName`, `versionCode`, `minSdk 30`, `targetSdk 30`, ABI `arm64-v8a`).
4. Подпись APK — debug-ключ сборщика. Хэш подписи на ГУ не проверяется.
5. Положил APK и `SHA256SUMS.txt` в `raw/acceptance/run3/`. Git их не хранит (`/raw/` в `.gitignore`).
6. Подготовил папки для результатов: `raw/acceptance/run3/photos/` и `raw/acceptance/run3/log/`.

## После приёмки

1. Передай агенту заполненный отчёт, фото и Журнал. Формат описан в [report-template.md](report-template.md).
2. Агент соберёт итоговый отчёт `docs/acceptance/report.md` и закроет строки R01–R27.
3. Серийник Модуля, имя компьютера и пользователя в публичный отчёт не попадают.
4. После успешной приёмки агент обновляет README (тикет #115).
