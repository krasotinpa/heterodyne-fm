# Приёмка MVP на ГУ: подготовка

Это инструкция для владельца. Она готовит всё до выезда к автомобилю.
Сами проверки описаны в [test-plan.md](test-plan.md). Форма результатов — в [report-template.md](report-template.md).
Тикет приёмки: [#89](https://github.com/krasotinpa/super-radio-android/issues/89).

## Итог

1. APK готов: `heterodyne-fm-0.1.0-debug.apk`, сборка из коммита `1164918`.
2. Нужны: SSD (exFAT или FAT32), переходник OTG, Модуль с антенной, телефон для фото и видео.
3. Время: около 2 часов, из них 30 минут — непрерывный приём.
4. Автомобиль стоит. Громкость ГУ малая. Это правило безопасности из AGENTS.md.

## Что взять с собой

| № | Предмет | Зачем |
|---|---|---|
| 1 | SSD с файловой системой exFAT или FAT32 | Перенос APK на ГУ и вывод Журнала с ГУ |
| 2 | Переходник OTG (USB-C) | SSD и Модуль подключаются к одному разъёму ГУ |
| 3 | Модуль и антенна | Приём радио |
| 4 | Телефон | Фото экрана ГУ, короткие видео |
| 5 | Распечатанный [test-plan.md](test-plan.md) или второй экран | Чек-лист шагов |
| 6 | Часы или таймер на телефоне | 30 минут приёма |

Нужна ещё хотя бы одна **AM-станция**, которую слышно в вашем месте. Если её нет, проверки AM остаются «не проверено». Это допустимо.
Нужно приложение навигатора на ГУ. Для проверки фокуса нужен ещё один плеер (например, FMPLAY, как в прошлых проверках).

## Шаг 1. Получить APK

Файлы лежат на компьютере в WSL-дистрибутиве `Ubuntu`, в папке `raw/acceptance/` репозитория.

```text
Windows-путь:  \\wsl$\Ubuntu\home\user\sources\super-radio-android\raw\acceptance\
Файлы:         heterodyne-fm-0.1.0-debug.apk
               SHA256SUMS.txt
```

1. Открой этот путь в проводнике Windows.
2. Скопируй оба файла в **корень SSD**.
3. Безопасно извлеки SSD.

Контрольная сумма APK:

```text
d71bbbd41e19c85f759319fb58e175b1cf13737bf2374cb6cde405c7d3eeeb32
```

Если хочешь проверить SSD: в PowerShell выполни `Get-FileHash E:\heterodyne-fm-0.1.0-debug.apk -Algorithm SHA256`. Замени `E:` на букву SSD. Результат должен совпасть с суммой выше.

## Шаг 2. Подготовить отчёт

1. Создай на телефоне или в чате заметку и скопируй в неё таблицу из [report-template.md](report-template.md).
2. На каждом шаге плана записывай статус и комментарий.
3. Фото называй номером шага: `T05-1.jpg`, `T05-2.jpg`. Если телефон не даёт задать имя, снимай по порядку и пиши в заметке: «фото 17 = шаг T05».

## Шаг 3. Что нужно знать про приложение

1. Приложение называется **Heterodyne FM**. Установка идёт из файла, как у прошлого Super Radio Probe.
2. Приложение не запускается само. Запускай его вручную из списка приложений.
3. Звук включается только кнопкой «Играть» или выбором Станции.
4. Приложение создаёт Журнал само. Журнал переживает перезагрузку ГУ. Вручную его включать не нужно.
5. Экран движения называется «Эфир». Режим стоянки открывается кнопкой «Стоянка» вверху справа.
6. Установка поверх прошлой версии работает, если подпись та же. При ошибке «Приложение не установлено» удали старое Heterodyne FM и установи снова.

## Шаг 4. Правила безопасности

1. Автомобиль стоит. Ручной тормоз включён.
2. Громкость ГУ малая. При громком звуке или треске нажми «Стоп».
3. Приложение шлёт Модулю только команды из списка `command-catalog.md`. Других команд в нём нет.
4. Не нажимай в режиме разработчика кнопки, которых не просит план.
5. Не делай сброс, обновление прошивки и другие действия с Модулем вне плана.
6. Модуль и SSD используют **один разъём**. Не подключай оба одновременно.

## Шаг 5. Что делает агент до выезда

1. Собрал APK: `./gradlew test lint assembleDebug` завершился с кодом 0.
2. Записал SHA-256 и версию: `versionName 0.1.0`, `versionCode 1`, `minSdk 30`, `targetSdk 30`, ABI `arm64-v8a`.
3. Подпись APK — debug-ключ сборщика. Хэш подписи на ГУ не проверяется.
4. Копия APK лежит локально в `raw/acceptance/`; Git её не хранит (`/raw/` в `.gitignore`).

## После приёмки

1. Передай агенту заполненный отчёт, фото и Журнал. Формат описан в [report-template.md](report-template.md).
2. Агент соберёт итоговый отчёт `docs/acceptance/report.md` и закроет строки R01–R27.
3. Серийник Модуля, имя компьютера и пользователя в публичный отчёт не попадают.
4. После успешной приёмки агент обновляет README (тикет #115).
