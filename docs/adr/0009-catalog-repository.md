# ADR 0009: Справочник в отдельном репозитории

Статус: принято владельцем 28.10.2026 на grilling-сессии #263. Уточняет определение Справочника в `CONTEXT.md`.

## Контекст

1. Справочник Станций и список Регионов зашиты в приложение: два файла в `assets/catalogs/`, Москва и Ярославль. Константы `moskva` и `yaroslavl` стоят в `StationsState` и в `StationsJson`.
2. Регионов будет больше 50. Данные соберут владелец и соавторы из разных источников.
3. ГУ часто стоит без интернета. Приложение до сих пор не использует сеть.
4. Автор vcfm.ru разрешил владельцу использовать данные сайта. Явной лицензии на сайте нет.

## Решение

1. **Репозиторий данных.** Справочник лежит в отдельном репозитории. Приложение берёт только релиз репозитория, не ветку `main`.
2. **Снимок в APK.** В APK лежит снимок всех Регионов. Приложение работает без сети с первого запуска.
3. **Ручное обновление.** Пользователь запускает обновление в Режиме стоянки: онлайн или импортом ZIP-файла. В Режиме движения сети нет. Фоновых и автоматических запросов нет.
4. **Формат.** `index.json` хранит Ревизию набора и список Регионов: `id`, `name`, файл, SHA-256, Ревизию Региона. Каждый Регион лежит в своём файле формата `schema: 1`. Онлайн и ZIP используют один формат. Поле `order` не используется.
5. **Ревизия.** Ревизия — дата. Приложение принимает набор только с Ревизией новее текущей. «Вернуть встроенный Справочник» возвращает снимок из APK.
6. **Проверка.** SHA-256 защищает от повреждения. Подписи нет. Приложение проверяет содержимое: известная `schema`, уникальные `id`, частота проходит `isSelectableFrequency` для FM, размеры ограничены. Любое нарушение отвергает весь набор. Новый набор заменяет прежний атомарно.
7. **Подборки.** Обновление Справочника не меняет Подборки. Копия Станции остаётся как есть, даже если Станция исчезла, переименована или сменила частоту.
8. **Идентификаторы.** `id` Региона и Станции не переиспользуются и не переименовываются. Регион, пропавший из нового набора, остаётся у пользователя как Устаревший Регион, пока пользователь его не удалит.
9. **Список Регионов.** Экран читает Регионы из `index.json` активного набора и сортирует по `name` с русской коллацией.
10. **Состояние пользователя.** Сохранённое состояние получает `schema: 3`. `regions` хранит только Регионы с данными пользователя. Пустое состояние («Основной») создаётся при первом обращении. Декодирование не зависит от Справочника. `schema: 1` и `schema: 2` читаются без потерь. Неизвестный `selectedRegion` заменяется Москвой.
11. **Лицензия данных.** CC BY 4.0. Каждый Регион хранит `source`. Соавтор в PR подтверждает, что источник позволяет такое использование. Ответ автора vcfm.ru хранится в `PROVENANCE.md` репозитория данных без личных данных.
12. **Процесс.** PR соавтора проверяет CI общим скриптом, тем же набором правил, что и приложение. Владелец принимает PR вручную. Релиз по тегу пересчитывает SHA-256 и публикует `index.json` и ZIP. Хэши вручную не правятся.

## Рассмотренные варианты

1. **Данные по требованию, без снимка.** Отклонён: ГУ без сети остаётся без Справочника.
2. **Только Москва и Ярославль в APK.** Отклонён: 50 Регионов занимают около 250 КБ, а ради экономии придётся ходить в сеть.
3. **Автоматическое или фоновое обновление.** Отклонён: Справочник не должен меняться под водителем. Проверку новой Ревизии можно добавить отдельным тикетом.
4. **Подпись ed25519 на `index.json`.** Отклонён: худший исход подмены — неверные частоты. Ключ усложняет работу соавторов. `schema` и `index.json` готовы к подписи, добавить её можно новым ADR.
5. **Поле `order` в `index.json`.** Отклонён: параллельные PR соавторов дают конфликты.
6. **Удалять Подборки или Станции при исчезновении из Справочника.** Отклонён: теряются данные пользователя из-за ошибки редактора репозитория.
7. **Лицензии CC0 и ODbL.** Отклонены: CC0 не требует указания источника, ODbL сложнее нужного для списка частот.
