# ADR 0003: аудиофокус, фон и кнопки руля

Статус: принято владельцем 16.10.2026 на картировании спецификации Heterodyne FM v1 ([карта](https://github.com/krasotinpa/super-radio-android/issues/27), билет [«Аудиофокус, фон и кнопки руля: политика приложения»](https://github.com/krasotinpa/super-radio-android/issues/38)).

## Контекст

1. Проверка на ГУ 16.10.2026 ([g2-media-report.md](../research/g2-media-report.md), [g2-autostart-report.md](../research/g2-autostart-report.md)) дала такие факты:
   - Подсказка навигатора радио не приглушает. В журнале один фокус `LOSS`, без `DUCK` и без возврата `GAIN`. Наш поток шёл без потерь.
   - ⏮ и ⏭ доходят до приложения как `PREVIOUS`/`NEXT`. Долгое нажатие: метка через ~0,8 с, затем ~20 повторов в секунду. Кнопки паузы на руле нет.
   - Выключение двигателя обесточивает ГУ. Приложение не запускается само.
   - После работы штатного «Радио» кнопка ⏭ до Probe не дошла, хотя `MediaSession` штатного приложения оставалась активной.
2. Радио — живой эфир. Остановка из-за чужого `LOSS` без возврата оставила бы водителя в тишине.
3. Источник единственного `LOSS` не установлен.

## Решение

1. **Фокус.** Приложение запрашивает `AudioFocusRequest` с `USAGE_MEDIA` перед началом звука.
   - `LOSS` (постоянная потеря): звук продолжается. Приложение не останавливается.
   - `LOSS_TRANSIENT_CAN_DUCK`: громкость 30 %. `GAIN` возвращает 100 %.
   - `LOSS_TRANSIENT`: звук выключается (mute), поток от Модуля идёт дальше. `GAIN` возвращает звук.
   - Если ГУ не присылает сигнал, приложение ничего не приглушает само. Навигатор в v1 приглушается только сигналами фокуса.
2. **Фон.** Foreground service с типом `mediaPlayback` и уведомлением живёт, пока идёт звук. Остановка звука завершает сервис.
   Состояние (Регион, Набор, станция, диапазон) приложение пишет при каждом изменении, не при выходе.
3. **Руль.** Пока сервис работает, `MediaSession` активна (`setActive(true)`, `PLAYING`).
   - ⏭ и ⏮: следующая и предыдущая станция Набора.
   - Долгое нажатие: один Шаг по первой метке `FLAG_LONG_PRESS`. Повторы ~20/с игнорируются.
   - Возврат кнопок после чужого плеера: при действии пользователя (кнопка «Играть», выбор станции) приложение запрашивает фокус и заново вызывает `setActive(true)`. Способ проверяется на ГУ.
4. **Запуск** — вручную ([проверка автозапуска](https://github.com/krasotinpa/super-radio-android/issues/63)). Пока звук остановлен, сервиса нет и руль приложению не служит.

## Последствия

1. Постоянный `LOSS` игнорируется вопреки обычному правилу Android. Риск: наложение звука стороннего плеера. Владелец принимает его: тишина хуже.
2. Приглушение без сигнала ГУ не работает. Если нужно, решение пересматривается новым ADR после измерений.
3. Возврат руля — гипотеза до прогона на ГУ. Если `setActive(true)` с фокусом не помогает, проверяется пересоздание `MediaSession`.
4. Остаются открытыми: время жизни приложения после выключения двигателя, источник `LOSS`.
