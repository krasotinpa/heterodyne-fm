# ADR 0005: автозапуск последней Станции

Статус: принято владельцем 26.10.2026 на grilling-сессии ([#173](https://github.com/krasotinpa/heterodyne-fm/issues/173)).

## Контекст

1. Приёмка #89 (T12): после запуска приложения и возврата Модуля радио ждёт «Старт». Владелец хочет, чтобы оно играло само.
2. Whitelist (command-catalog) разрешает playSelect и BAND «только по действию пользователя, без автоповтора».
3. ГУ обесточивается вместе с двигателем без плавного завершения.

## Решение

1. **Исключение из «только по действию пользователя».** Автозапуск включён по умолчанию, переключатель «Играть последнюю Станцию при запуске» в Настройках (раздел «Запуск»).
2. **Триггеры.** Открытие приложения вручную; возврат Модуля. Холодная загрузка ГУ сводится к открытию приложения: автозапуска самого приложения в v1 нет.
3. **Границы.** Только последняя сохранённая Станция; один раз на событие; без автоповтора; не больше одного автозапуска за 30 с; только при `lastPlayed = true` и валидном состоянии; лимиты строк whitelist (1 с, 2 с) не снимаются. Действие пользователя до автозапуска отменяет его.
4. **Фокус и громкость.** Сначала аудиофокус; без него команд нет, строка «Нет фокуса, нажмите Старт», повтора нет. Системную громкость не трогаем. Потеря фокуса после старта — по ADR 0003.
5. **Порядок.** requestAllInfo; если `0x22` совпал с целью — playSelect не шлём; иначе Переход по R26 (BAND, пауза 2 с, playSelect).
6. **Состояние.** Регион, Подборка, Станция, диапазон, `lastPlayed` пишутся при каждом изменении атомарно. «Стоп» пишет `lastPlayed = false`. Нет записи или она повреждена — ноль команд.

## Последствия

1. R25, R26 (правило 5, «Модуль отключён») и критерий MVP п. 5 изменены.
2. Строки playSelect и BAND в command-catalog требуют основания «или автозапуск по R25» — внесены владельцем в этом PR.
3. Нужны тесты на FakeTransport (R25) и проверка на ГУ.
