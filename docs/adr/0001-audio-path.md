# ADR 0001: звук — свой изохронный приём через usbfs

Статус: принято владельцем 15.10.2026. Пересмотр — по результату G2 на ГУ.

## Контекст

1. Модуль отдаёт звук по USB Audio Class 1: IF 1 alt 1, изохронный EP `0x81`, асинхронный, 48 кГц, 16 бит, 2 канала ([descriptor-map.md](../research/descriptor-map.md)).
2. В дескрипторе ошибка: терминал с ID 1 имеет подтип Output Terminal при полях Input Terminal.
   Windows не создаёт устройство записи. Linux 6.18 `snd-usb-audio` проваливает разбор mixer (`-ENODEV`) и удаляет карту ([g6a-report.md](../research/g6a-report.md)).
3. Свой захват через libusb работает: речь на FM 90,3 МГц слышна чисто; два захвата по ~30 с без плохих пакетов (G6a).
4. Поток — непрерывные байты: кадры пересекают границы пакетов (192 и иногда 198 байт). Начало кадра нужно находить.
5. Java API Android (`UsbDeviceConnection`, `UsbRequest`) не поддерживает изохронные передачи. Bulk и control он поддерживает.
6. Приложение производителя решает ту же задачу через libusb поверх файлового дескриптора из `UsbManager`, без root ([vendor-apk-analysis.md](../research/vendor-apk-analysis.md)).
7. ГУ: Android 11 (API 30), вероятно SA8155P, ABI по открытым источникам `arm64-v8a` ([g2-head-unit.md](../research/g2-head-unit.md)).

## Решение

1. Звук принимает своё нативное ядро: изохронные URB через usbfs (`USBDEVFS_SUBMITURB`/`REAPURB`) на файловом дескрипторе `UsbDeviceConnection`.
   Разрешение — стандартный запрос `UsbManager`; root не нужен.
2. Интерфейс 1 захватывается с `force = true` и переводится в alt 1 через Java API (`claimInterface`, `setInterface`). Системный драйвер, если он занял интерфейс, отключается этим захватом.
3. Принятые байты выравниваются по кадрам один раз в начале потока и отдаются в `AudioTrack` (`USAGE_MEDIA`, PCM 16 бит, 48 кГц, стерео).
4. Команды радио идут Java API: `bulkTransfer` на IF 3, EP `0x03`/`0x83`. Управляющие запросы CDC (line coding, DTR/RTS) не шлются: G6a показала, что Модуль работает без них.
5. Нативная библиотека собирается NDK под `arm64-v8a` и `armeabi-v7a`. Системный путь (`AudioRecord` с `TYPE_USB_DEVICE`) не используется, пока G2 не покажет на ГУ USB-аудиовход Модуля.

## Почему usbfs, а не libusb

| Вариант | За | Против |
|---|---|---|
| usbfs напрямую | ~100 строк C, без сторонних зависимостей; тот же механизм, что libusb на Linux | Своя работа с URB и ошибками |
| libusb | Проверен в G6a и у производителя | Сборка и обновление сторонней библиотеки под NDK |
| Системный USB-аудиовход | Без нативного кода | В Linux 6.18 не работает; на ГУ, вероятно, тоже |

Если usbfs на ГУ окажется недоступен для приложения (политика SELinux или прав на `/dev/bus/usb`), переход на libusb ничего не изменит: libusb использует тот же usbfs. Тогда это blocker G2.

## Последствия

1. В проект входят NDK и нативный код. Toolchain закрепляется в сборочном скрипте.
2. Нужны: поиск начала кадра; компенсация дрейфа асинхронного источника при долгой работе; аудиофокус; реакция на отключение USB.
3. Прототип проверяется вместе с диагностическим приложением G2 одной поездкой: если звук на ГУ слышен, решение подтверждено.
4. При первом захвате система показывает предупреждение, что приложение сможет записывать звук через USB-устройство; это ожидаемо.
