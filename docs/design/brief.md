# Бриф для Claude Design: внешний вид Heterodyne FM

Тикет: [#118](https://github.com/krasotinpa/super-radio-android/issues/118). Требования: [requirements.md](../requirements.md), строки R17, R18, R21–R23.
Бриф пишет владелец продукта. Claude Design разрабатывает внешний вид. Дизайн принят в [#119](https://github.com/krasotinpa/super-radio-android/issues/119). Реализацию в Compose делает Codex по тикетам [#131](https://github.com/krasotinpa/super-radio-android/issues/131), [#132](https://github.com/krasotinpa/super-radio-android/issues/132), [#133](https://github.com/krasotinpa/super-radio-android/issues/133), [#134](https://github.com/krasotinpa/super-radio-android/issues/134).

## Итог

1. Нужно переработать внешний вид всех экранов приложения.
2. Результат — интерактивный HTML-прототип и таблица токенов (раздел «Что вернуть»).
3. Приложение работает на штатном ГУ автомобиля. Экран 15,6″, landscape. Водитель смотрит на него на ходу.
4. Главное правило: элемент управления и объект на экране понятны с одного взгляда.
5. Поведение не меняется. Меняются форма, цвет, размеры и состав экранов по этому брифу.

## Термины

Приложение называется Heterodyne FM (H-FM). Весь текст интерфейса — по-русски.

| Слово | Значение |
|---|---|
| Модуль | USB-радиомодуль. Принимает FM и AM |
| ГУ | Штатное Android-головное устройство автомобиля |
| Станция | Радиостанция: имя, диапазон, частота |
| Справочник | Встроенный список Станций Региона. Пользователь его не правит |
| Подборка | Список Станций, который собрал пользователь. Порядок задаёт он. У Региона несколько Подборок, одна активная |
| Регион | Москва или Ярославль. Свой Справочник и свои Подборки |
| Переход | Установка Модуля на Станцию |
| Шаг | Сдвиг частоты на одно деление сетки |
| Поиск | Переход к ближайшей Станции с сигналом |
| Лупа | Увеличенная полоса Станций вокруг точки касания шкалы |
| Тема | Светлая или тёмная. Выбор: Авто, Светлая, Тёмная |
| Палитра | Готовый набор цветов со светлой и тёмной версией |
| Режим движения («Эфир») | Экран для водителя на ходу |
| Режим стоянки | Экран для стоящего автомобиля: Подборки, Настройки, Диагностика, «О приложении» |
| Режим разработчика | Скрытое расширение Режима стоянки: поток кадров и кнопки команд |


## Что менять

1. **Справочник в несколько рядов.** Сейчас Справочник — одна лента плашек. Нужны ряды с прокруткой по вертикали. Число рядов подбери по холсту.
2. **Лупа на шкале** (раздел «Лупа»).
3. **Шкала ярче.** Подписей Станций на шкале нет. Остаются отметки Станций. У Станций активной Подборки отметки ярче. Подписаны текущая частота и края диапазона.
4. **FM/AM** — сегментный переключатель из двух половин. Видны обе подписи, активная половина залита.
5. **Кнопки.** Рамки не обязательны. Кнопка узнаётся по форме, заливке и значку. Сейчас кнопки Поиск, Шаг и Стоянка выглядят как текст.
6. **Подсветка перетаскиваемой Станции** в редакторе Подборок. Плашка приподнята. Место вставки показано линией и подсветкой слота.
7. **Палитра, светлая и тёмная Тема.** Раздел «Темы и Палитры».
8. **Иконка приложения.** Собственная: шкала с бегунком. Без логотипов станций и без знаков автопроизводителя.
9. **Место под RDS.** Раздел «RDS».
10. **Все экраны.** Включая Диагностику и Режим разработчика. Они тоже должны выглядеть аккуратно.

## Ограничения

### Экран ГУ

1. Окно приложения не занимает весь экран. Системная оболочка ГУ закрывает верхнюю панель, нижнюю панель климата и левую колонку виджетов. Окно занимает около 70 % ширины экрана. Оно шире, чем высокое: примерно 1,9 : 1.
2. Точный размер окна в dp не измерен. Опорная ширина — 1100 dp. Вёрстка должна работать при отклонении на ±15 % по ширине и по высоте.
3. Фото ГУ: [фото](#входные-материалы). Окно приложения видно на `…110448.jpg`. Оболочка без приложения — на `…110461.jpg`.

### Нажатия и скорость

1. Цель нажатия не меньше 48 px. У кнопок управления на ходу («Станция ◀ ▶», «Шаг ◀ ▶») цель больше.
2. UI отвечает на нажатие до 200 мс. Видимая реакция (состояние «нажата») появляется до 100 мс.
3. Все состояния показываются в обеих Темах и во всех Палитрах: обычная, нажата, выключена, активна, перетаскивается.

### Контраст

1. Текст: контраст не ниже 4,5:1.
2. Значки и границы: не ниже 3:1.
3. Требование действует в каждой Палитре и в каждой Теме. Укажи в токенах расчётные значения.

### Что нельзя показывать (R18)

Уровень сигнала, stereo, lock и RDS-текст не показываются: Модуль не подтвердил эти поля. В прототипе не рисуй ни одного элемента для них. Исключение — место под RDS (раздел «RDS»), оно свёрнуто.

### Что не менять

1. Поведение R24: кнопки руля (⏭/⏮ — Станция Подборки; долгое нажатие — Шаг).
2. Поведение R26: состояния Перехода, ошибки Модуля, очередь команд.
3. Состав функций Режима движения и Режима стоянки: не добавляй функций, которых нет в этом брифе.
4. Логотипов Станций нет, только текст.
5. Нет сети. Не используй веб-шрифты и внешние картинки: приложение работает офлайн. Шрифт должен быть системным или встраиваться в APK.

## Экраны

### Режим движения («Эфир»)

Состав (вариант B «Шкала», R21):

1. Верхняя строка: частота крупно, имя Станции, диапазон, Регион, переключатель FM | AM, Поиск ◀ ▶ (скрыты на ходу, место не занимается другими элементами), «Стоянка», строка RDS (свёрнута).
2. Шкала диапазона с бегунком подтверждённой частоты и отметками Станций.
3. Область Подборки: плашки Станций активной Подборки. Рядом переключатель Подборок.
4. Область Справочника: плашки в несколько рядов с прокруткой по вертикали.
5. По краям высокие кнопки «Станция ◀ ▶» (по Подборке) и «Шаг ◀ ▶».
6. Кнопка «Играть». Звук включается только ею или выбором Станции.

Покажи состояния: Модуль подключён и играет; Модуль не подключён; Переход идёт; ошибка Перехода; Подборка пуста; AM без Станций (Справочник AM пуст).

### Лупа

1. Лупа появляется, пока палец на шкале FM. После отпускания исчезает. В обычном состоянии её нет.
2. Лупа показывает полосу Станций Справочника вокруг точки касания. Станции увеличены. На них видны имена. Станции активной Подборки отмечены.
3. Выбор прилипает к ближайшей Станции. Свободных частот нет.
4. Палец закрывает часть шкалы. Размести Лупу так, чтобы палец её не перекрывал.
5. Переход выполняется один раз, при отпускании пальца на Станции.
6. Если увести палец за шкалу по вертикали, Лупа исчезает без Перехода. Покажи это как отдельное состояние: водитель должен видеть, что отмена сработала.
7. В AM Лупы нет. Частоту меняют «Шаг ◀ ▶».

Покажи в прототипе все шаги: касание, движение, смену Станции под пальцем, отпускание с Переходом, отмену.

### RDS

1. Под названием Станции есть строка под PS и RadioText. PS — имя Станции до 8 символов. RadioText — одна строка, длинный текст идёт бегущей строкой.
2. В v1 RDS выключен. Строка свёрнута и ничего не рисует. Экран не имеет пустого места и не прыгает при включении RDS позже.
3. Покажи два состояния: RDS выключен (так выглядит v1) и RDS включён (так будет после разбора протокола). Текст для макета возьми любой, он не настоящий.

### Режим стоянки

Боковое меню слева в окне приложения. Разделы:

1. **Подборки.** Редактор в две колонки: Справочник → Подборка. Порядок задаёт перетаскивание. Кнопка «Сохранить текущую частоту». Подсветка перетаскиваемой Станции и места вставки.
2. **Настройки.**
   1. Регион: Москва или Ярославль.
   2. Тема: Авто (по данным от ГУ), Тёмная, Светлая.
   3. Палитра: выбор из 3–4 готовых.
3. **Диагностика.** Версия, состояние связи с Модулем, экспорт Журнала на SSD с подсказкой «отключите Модуль и подключите SSD».
4. **О приложении.** Версия, источник данных Справочника (vcfm.ru со ссылкой).

### Режим разработчика

Скрытое расширение Диагностики. Содержит поток кадров, счётчики звука, байт `+7`, кнопки команд. Оформи как аккуратный технический экран: моноширинный шрифт для кадров, кнопки команд как обычные кнопки. Новых функций не добавляй.

## Темы и Палитры

1. Три варианта Темы: Авто, Тёмная, Светлая. Авто следует данным от ГУ. Если данных нет, Авто даёт тёмную Тему.
2. Нужны 3–4 Палитры. У каждой есть светлая и тёмная версия.
3. Стиль собственный. Не подстраивайся под системные цвета ГУ (бирюзово-голубой акцент, тёмно-серые карточки). Приложение должно отличаться от оболочки.
4. Все цвета заданы токенами. Смена Палитры не требует правки компонентов.
5. Для каждой пары «Палитра × Тема» посчитай контраст ключевых пар (текст на фоне, значок на фоне, граница на фоне) и приведи в таблице токенов.
6. Пользователь выбирает Палитру в «Настройках». Произвольного выбора цвета нет: контраст нельзя гарантировать.

## Что вернуть

1. **Интерактивный HTML-прототип** в одном файле. Он показывает все экраны и состояния из раздела «Экраны». В прототипе работает Лупа, смена Темы и Палитры, перетаскивание в редакторе Подборок.
2. **Таблица токенов:**
   1. Цвета каждой Палитры в светлой и тёмной версии, с контрастом ключевых пар.
   2. Шрифт, размеры и межстрочное расстояние в dp и sp.
   3. Размеры компонентов и отступы в dp. Цели нажатия не меньше 48 px.
   4. Радиусы, тени, толщины линий.
3. **Состояния компонентов:** обычная, нажата, выключена, активна, перетаскивается — для кнопок и плашек, в обеих Темах.
4. **Иконка приложения:** исходник и версия для адаптивной иконки Android.
5. **Список допущений**, которые ты сделал из-за недостающих данных (например, размер окна).

## Критерии приёмки

1. Все экраны и состояния из раздела «Экраны» есть в прототипе.
2. Контраст не ниже 4,5:1 для текста и 3:1 для значков и границ в каждой паре «Палитра × Тема».
3. Все цели нажатия не меньше 48 px.
4. Нет элементов для неподтверждённых полей (R18).
5. Нет элементов, которые меняют поведение R24 и R26.
6. Вёрстка работает при размере окна 1100 dp ±15 %.
7. Владелец принимает прототип. После приёмки реализация идёт по тикетам [#131](https://github.com/krasotinpa/super-radio-android/issues/131)–[#134](https://github.com/krasotinpa/super-radio-android/issues/134).
