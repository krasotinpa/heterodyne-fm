## USB

Без Модуля система видит два устройства:

1. `0dd8:2320` NetacPortableSSD — SSD владельца, mass storage.
2. `12d1:15c3` Huawei «19MC Data Communication Module», `/dev/bus/usb/004/002` — встроенный модем ГУ, шесть интерфейсов. Агент к нему не обращался и не обращается.

С Модулем — `/dev/bus/usb/002/003`: тот же bus 002, что у SSD, то есть тот же разъём.
Строки дескриптора: `STMicroelectronics` / `DAB usb bridge`.

| IF | alt | Класс | EP |
|---|---|---|---|
| 0 | 0 | 1/1/0 Audio Control | — |
| 1 | 0 | 1/2/0 Audio Streaming | — |
| 1 | 1 | 1/2/0 Audio Streaming | `0x81` iso, max 312 |
| 2 | 0 | 2/2/1 CDC ACM | `0x84` interrupt, max 8 |
| 3 | 0 | 10/0/0 CDC Data | `0x03`, `0x83` bulk, max 64 |

Это совпадает с [descriptor-map.md](descriptor-map.md).

### Разрешение

`hasPermission` вернул `true` для Модуля, SSD и модема. Приложение запрашивает разрешение только для Модуля, и строка «Запрос разрешения» — «не запрашивалось».
Значит, `requestPermission` не вызывался: доступ уже был в момент первого отчёта с Модулем.
Видел ли владелец диалог доступа к USB, в отчёте нет. Для SSD и модема приложение ничего не запрашивало, а доступ есть.
Гипотеза: прошивка ГУ выдаёт доступ к USB любому приложению без диалога. Проверка — отчёт сразу после переподключения Модуля без нажатия «Разрешить».

## Аудиоустройства

Список одинаков в трёх состояниях: без Модуля, с Модулем до теста, с Модулем во время захвата.

1. Выходы: 9 шин типа 21 (`TYPE_BUS`), 48 кГц, 2 канала: `BUS00_MEDIA`, `BUS01_SYS_NOTIFICATION`, `BUS02_NAV_GUIDANCE`, `BUS03_PHONE`, `BUS08_FRONT_PASSENGER`, `BUS10_BTMEDIA`, `BUS11_TTS_VR`, `BUS13_RING`, `BUS16_REAR_SEAT`.
2. Входы: типы 21, 15 (`TYPE_BUILTIN_MIC`) и 25 (`TYPE_REMOTE_SUBMIX`), среди них `BUS04_INPUT`, `BUS09_INPUT_FRONT_PASSENGER`, `BUS17_INPUT_REAR_SEAT`.
3. Типа 11 (`TYPE_USB_DEVICE`) нет.

Android не создал USB-аудиовход для Модуля. Это совпадает с отказом `snd-usb-audio` в Linux ([g6a-report.md](g6a-report.md)).
Причина на ГУ не измерялась: `dmesg` без ADB недоступен.
Звук приложения ушёл по маршруту `USAGE_MEDIA` по умолчанию; какая шина его играла, не измерялось.

Выводы:

1. Изохронный приём через usbfs на файловом дескрипторе `UsbDeviceConnection` работает без root. `claimInterface(force)` и `setInterface(alt 1)` прошли.
2. Недобор почти постоянный: 44–46 КБ, около 0,24 с. Это задержка старта потока, а не дрейф.
   Скорость между 7,5 и 22,7 с — 190 977 байт/с, ниже 192 000 на 0,5 %. Время на экране округлено до 0,1 с, отсюда погрешность ±1,3 % на этом интервале. Дрейф за 30 с не обнаружен.
3. Смещение кадра 2 — как во всех трёх захватах G6a на ПК. Теперь это четыре сессии на двух хостах; причина по-прежнему не установлена.
4. Уровень около −16 dBFS — сигнал станции, а не тишина или шум.

## Не проверено

1. Шаг 7: реакция встроенных «Радио» и «USB» на Модуль. Владелец о ней не сообщал.
2. Шаг 9: экран после отключения Модуля не сфотографирован.
3. Показывался ли диалог USB при подключении Модуля.
4. Какая станция играла. Совпадение с 90,3 МГц не подтверждено.
5. Работа дольше 30 с: дрейф, нагрев, повторный тест после отключения.
6. Радиокоманды с ГУ: в G2 их не было.

## Что это значит для приложения

1. ADR 0001 подтверждён: usbfs, `AudioTrack`, `claimInterface(force)`. Путь через `AudioRecord` исключён измерением.
2. Сборка — только `arm64-v8a`; `armeabi-v7a` можно убрать.
3. Компенсация дрейфа остаётся по ADR: за 30 с дрейф не виден, нужен прогон в минутах.
4. Если гипотеза о разрешении подтвердится, диалог USB на этом ГУ не мешает. Код запроса разрешения всё равно нужен.
