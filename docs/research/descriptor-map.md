# G1: карта USB-дескрипторов Модуля

Дата сессии: 14 октября 2026 года, 16:26–16:33 UTC. Уровень воздействия B: COM-порт не открывался, звук не включался.
Сбор выполнил Claude Code в Windows по [g1-windows-plan.md](../plans/g1-windows-plan.md); интерпретация выполнена в WSL.

## Итог

Модуль — составное USB-устройство Full Speed из двух функций, связанных IAD:

```text
Модуль 0483:5740 (Full Speed, 1 конфигурация, 4 интерфейса)
├─ IAD 1: USB Audio Class 1 ── MI_00 ── Windows: usbaudio
│   ├─ IF 0  Audio Control: вход «Radio Receiver»? → Feature Unit (Mute) → USB streaming
│   └─ IF 1  Audio Streaming: alt 0 пусто; alt 1 EP 0x81 iso IN, PCM 48 кГц, 2 канала, 16 бит
└─ IAD 2: CDC ACM ─────────── MI_02 ── Windows: usbser, COM5
    ├─ IF 2  CDC Control: EP 0x84 interrupt IN, 8 байт
    └─ IF 3  CDC Data:    EP 0x03 bulk OUT, EP 0x83 bulk IN, 64 байта
```

Звуковая функция есть, но Windows не создала устройство записи. В дескрипторах найдены две ошибки прошивки.

## Звуковая функция

1. Audio Control: заголовок UAC 1.00, коллекция из одного интерфейса потока (IF 1).
2. Feature Unit ID 2, источник ID 1, управление master: только Mute (`bmaControls 01 00`).
3. Output Terminal ID 3, тип 0x0101 (USB streaming), источник ID 2.
4. Audio Streaming alt 1: формат PCM, Type I, 2 канала, 2 байта на отсчёт, 16 бит, одна частота 48 000 Гц.
5. 48 000 Гц × 2 канала × 2 байта = 192 байта за кадр 1 мс; endpoint допускает до 312 байт.

### Ошибка входного терминала

USBView не разобрал блок `0C 24 03 01 10 07 00 02 03 00 00 00`.
Длина 12 байт соответствует Input Terminal UAC1, но подтип равен `0x03` (Output Terminal) вместо `0x02`.
Если читать его по формату Input Terminal: ID 1, тип `0x0710`, без парного терминала, 2 канала, конфигурация каналов `0x0003` (левый и правый).
Тип `0x0710` в спецификации UAC1 Terminal Types — «Radio Receiver». Feature Unit ссылается на ID 1 как на источник.
Это прочтение — гипотеза: оно согласуется со всеми полями, но прошивка формально объявила другой подтип.

### Windows не создала устройство записи

После подключения добавилось только устройство MEDIA `MI_00` с драйвером `usbaudio` (`wdma_usb.inf`). Нового AudioEndpoint не появилось.
Гипотеза: Windows не построила аудиотопологию из-за ошибки входного терминала. Не проверено.
Приложение производителя не зависит от системного драйвера: оно отключает его и читает iso-поток через libusb ([vendor-apk-analysis.md](vendor-apk-analysis.md)).

## Функция CDC

Функциональные дескрипторы показаны USBView как hex:

| Байты | Дескриптор | Поля |
|---|---|---|
| `05 24 00 10 01` | Header | CDC 1.10 |
| `05 24 01 00 01` | Call Management | возможности 0x00, интерфейс данных **1** |
| `04 24 02 02` | ACM | возможности 0x02: line coding и serial state |
| `05 24 06 00 01` | Union | управляющий **0**, подчинённый **1** |

Call Management и Union указывают на интерфейсы 0 и 1. Это интерфейсы звука, а CDC занимает 2 и 3.
Это ошибка прошивки, похожая на неисправленный шаблон ST. Выбирать интерфейсы CDC по Union нельзя.
Приложение производителя ищет интерфейсы по классу (`0x02` и `0x0A`), поэтому ошибка ему не мешает.

## Сопоставление Windows и USB

| PnP | Интерфейсы | Драйвер |
|---|---|---|
| Родитель (составное устройство) | все | `usbccgp` |
| `MI_00` «DAB usb bridge», класс MEDIA | 0 и 1 (IAD 1) | `usbaudio` |
| `MI_02` «USB Serial Device (COM5)», класс Ports | 2 и 3 (IAD 2) | `usbser` |

Отдельных устройств `MI_01` и `MI_03` нет: `usbccgp` группирует интерфейсы по IAD.
`MI_02` в Windows не означает Android `getInterface(2)` автоматически. Здесь номер совпал с `bInterfaceNumber` 2, но индекс в Android проверяется в G2.

## Следствия для Android

1. Интерфейсы CDC выбираются по классу и номеру (2 и 3), а не по Union.
2. Java API `UsbDeviceConnection` не поддерживает изохронные передачи. Для iso-потока нужен нативный код (usbfs или libusb) либо системный драйвер USB Audio ГУ.
3. Сработает ли системный драйвер ГУ с ошибочным входным терминалом, неизвестно. Это проверка G2/G6.

Выбор между нативным захватом и системным драйвером — кандидат в ADR после G2.

## Ограничения

1. Дескрипторы прочитаны в Windows. Android может перечислить устройство иначе; проверка — G2.
2. Звук не включался, поток не читался: альтернатива 1 не активировалась.
3. Нагрев Модуля не оценивался.
