# Статический анализ приложения производителя

Дата: 14 октября 2026 года. Уровень воздействия A: APK не устанавливался и не запускался, Модуль не подключался.

## Итог

Приложение производителя явно рассчитано на Модуль: его USB-фильтр содержит `0483:5740`.
Код приложения описывает кадр по модели B, задаёт таблицу команд и разбирает входящие типы `0x21`–`0x29`.
Звук идёт по USB Audio Class (по именам символов — UAC1): приложение захватывает изохронный поток через libusb и играет его через `AudioTrack`.
Всё ниже — свойства кода приложения. На Модуле ни одна команда ещё не проверена. Whitelist остаётся пустым.

```text
APK → USB-фильтр → CDC 115200 8N1 → кадр FA 55 (модель B) → команды 0x80 xx
    └→ USBAudio (libusb, UAC1, iso) → AudioTrack 48 кГц
```

## USB

1. `res/xml/device_filter.xml` содержит `2E88:4605` и `0483:5740`. `DabService.connect` выбирает устройство с одной из этих пар.
2. Управление: форк `usb-serial-for-android`, класс `CdcAcmSerialDriver`. Порт 0, `setParameters(115200, 8, 1, 0)`.
3. CDC-драйвер ищет интерфейсы класса `0x02` и `0x0A` и захватывает их с `force=true`.
4. При открытии приложение шлёт только `SET_LINE_CODING` (`0x20`): 115200 8N1.
5. `SET_CONTROL_LINE_STATE` (`0x22`) в драйвере есть, но приложение не вызывает `setDTR`/`setRTS`. DTR и RTS оно не выставляет.
6. Звук: класс `au.id.jms.usbaudio.USBAudio` и `libUSBAudio.so` поверх `libusb100.so`.
7. В `libUSBAudio.so` есть `scan_audio_interface`, `set_sample_rate_v1`, `fill_iso_transfer`, `_uac_process_payload_iso`, `libusb_detach_kernel_driver`.
8. Java-часть по умолчанию задаёт 48 000 Гц и создаёт `AudioTrack` (поток `STREAM_MUSIC`, 16 бит, моно или стерео по числу каналов).

## Кадр

`DabService.send` и `DabService.onNewData` описывают одинаковый кадр в обе стороны:

```text
FA 55 | SEQ (+2) | LEN (+3..+4, big-endian) | BODY (LEN байт)
полная длина = LEN + 5; последний байт BODY = (−Σ байтов от +5 до предпоследнего) mod 256
```

1. SEQ в TX — счётчик приложения: `nPacketNum`, растёт на 1 по модулю 256 на каждую команду.
2. Разбор RX буферизует до 8 192 байт, ищет `FA 55`, ждёт полный кадр и проверяет сумму.
3. Кадр с неверной суммой приложение передаёт в UI с флагом ошибки. Обработчики `0x22`, `0x23`, `0x26`–`0x29` такой кадр отбрасывают; `0x21`, `0x24`, `0x25` — нет.

Это противоречит модели A из G0 и согласуется с моделью B из `evidence/capture-method.md`.

Байт `<b7>` в DAD: `(cid / 256) & (mode_flags_bit * 32 + 15)`. Точный вид выражения не установлен: DAD мог исказить приоритет операций.

Поля `mcufile` и `fileInputStream` похожи на заготовку обновления прошивки. Рабочего пути прошивки в APK нет.

Команды установки произвольной частоты в таблице нет. Частота меняется шагом, поиском или выбором из списка по cid/sid.

## Входящие типы

`MainActivity.onDataChange` ветвится по байту +5:

| Тип | Разбор приложения | Поля |
|---|---|---|
| `0x21` | Список станций | b6: `0x80` — очистить список, `0x40` — завершить; записи по 23 байта: sid (2), байт режима/избранного/cid hi, cid lo, неописанный байт, кодировка, 17 байт текста |
| `0x22` | Текущая станция | режим `(b6>>5)&3` (b6 — байт +6 Кадра, `тело[1]`), cid, sid, ансамбль, состояние, имя сервиса |
| `0x23` | Текст DAB | кодировка b6, текст |
| `0x24` | b6=0: сигнал = b7; b6=1: прогресс автопоиска b7 (0–100) | байты после +7 не читаются, см. ниже |
| `0x25` | Фрагменты изображения SLS | b6 — флаги начала и конца |
| `0x26` | Текст состояния | кодировка b7, 16 байт текста с +8 |
| `0x27` | Текст MCU | 16 байт с +6 |
| `0x28` | Регион FM | b6 |
| `0x29` | Иконка PTY | b6≠0: иконка `pty00<b6−1>` и значок избранного; b6=0: иконка `pty00<b7−1>`. Смысл PTY — гипотеза |

Режим: 0 — AM, 1 — FM, иначе DAB (`Utils.getModeText`). Кодировка текста: старший полубайт 6 — ASCII, 15 — UCS-2, иначе таблица EBU Latin.

## Длинный `0x24` в FM

В G4-4 Модуль в FM слал `0x24` с LEN 11: после байта +7 ещё семь байтов, +8…+14, затем сумма ([g4-4-report.md](g4-4-report.md), поправка в [g4-5-report.md](g4-5-report.md)).
Проверено 14 октября 2026 года по коду приложения:

1. `DabService` собирает Кадр, сверяет сумму и передаёт его целиком в `MainActivity.onDataChange` с флагом ошибки суммы. Сам он поля не разбирает; ветка `0x24` флаг не учитывает.
2. Ветка `0x24` в `onDataChange` читает только +6 и +7. b6=0: `nSignal = b7`, затем `updateSignal`. b6=1: прогресс автопоиска, при 100 индикатор скрывается.
3. `updateSignal` знает уровни 0–6, остальные показывает как 6. В FM b7 почти всегда 0 или 1 (G4-4, G4-5), поэтому приложение показало бы сигнал 0–1 из 6.
4. Байты +8…+14 не читает ни один класс приложения. Поиск по `p24[8]`…`p24[14]`, `length` и `subByte` в ветке `0x24` пуст.
5. Нативные `libUSBAudio.so` и `libusb100.so` — звук UAC и libusb; строк протокола Кадров в них нет.
6. Поле `RadioStation.stereo` объявлено, но нигде не заполняется. Текст «Stereo» встречается только в тестовом режиме UI.
   Состояние Mono/Stereo приложение показывает из текста `0x26` (`tvRadioState`), а не из байтов `0x24`.

Вывод: приложение производителя смысла семи байтов не раскрывает. Их значение можно установить только экспериментом,
например сравнением с антенной и без неё в FM. Гипотеза о метриках приёма FM остаётся непроверенной.

## Сверка с захватом G0

| Кадр в захвате | Чтение по коду приложения |
|---|---|
| `24 00 00 DC` × 49 | сигнал 0 |
| `26 04 00` + 16 × `20` + `D6` × 49 | пустой текст состояния, кодировка 0 |
| `29 00 0N cs` × 6 | иконка `pty00<N−1>`; N = 7, 8, 9, 10, 5, 6 |

Последовательный разбор по модели B проходит весь захват: 104 кадра, без рассинхронизации и ошибок суммы.
SEQ по порядку: 183…253, затем 0, затем 57…88. Переход 253→0 не является шагом по модулю 256: это сброс или склейка.
Гипотеза: сигнал 0 означает, что антенна при записи не была подключена. Не проверено.

## Ограничения

1. Приложение рассчитано на DAB-версию (режимы AM, FM, DAB). Совпадение набора команд для AM/FM-Модуля не проверено.
2. Какой интерфейс несёт звук и с какими alternate settings, покажет G1.
3. Кодирование частоты FM и AM в cid и sid не установлено.
4. `DabService.disconnect` вызывает `System.exit(0)`. Это особенность приложения, не протокола.
