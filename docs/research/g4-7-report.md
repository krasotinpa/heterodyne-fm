# G4-7: playSelect в FM и роль байта b7

Дата: 15 октября 2026 года. Уровень воздействия E: два кадра playSelect одобрены владельцем планом [g4-7-windows-plan.md](../plans/g4-7-windows-plan.md) (PR 50).
Сбор выполнил Claude Code в WSL через Windows PowerShell; анализ — `research-tools/analyze_session.py`.

## Итог

playSelect работает в FM. Кадр `80 82 20 1D 00 1D` перевёл Модуль с FM cid 28 «90.3 MHz» на cid 29 «90.4 MHz» за 26 мс.
Байт `<b7>` не задаёт диапазон. Кадр с `<b7>` = `00` и cid 28 оставил Модуль в FM и вернул «90.3 MHz» за 31 мс. Диапазон Модуль берёт из текущего состояния.
Побочных эффектов не видно: переподключения нет, `0x28` не приходил, звуков нет, нагрев слабый.
Каждый переход наблюдался один раз.

```text
Старт: FM cid 28 «90.3  MHz»
19:17:31 playSelect P1 (b7=20, cid 29)  +26 мс: FM cid 29 «90.4  MHz»
19:18:31 playSelect P2 (b7=00, cid 28)  +31 мс: FM cid 28 «90.3  MHz»
```

## Что подтверждено

| Кадр | Запрос | Ответ Модуля | Время |
|---|---|---|---|
| P1 | cid 29, `<b7>` = `20` | `0x22`: FM cid 29, «90.4  MHz» | 26 мс |
| P2 | cid 28, `<b7>` = `00` | `0x22`: FM cid 28, «90.3  MHz» | 31 мс |

1. Формула FM «МГц = 87,5 + 0,1 × cid» согласуется с cid 29 → 90,4. Это четвёртая точка вместе с G4-5 и G4-6.
2. Список `0x21` не менялся (одна запись FM cid 30 «90.5  MHz»), как в G4-6. Он не совпадает с текущей станцией cid 28; расхождение описано в [g4-6-report.md](g4-6-report.md).
3. В трассе 5 пакетов bulk OUT; байты и порядок совпали с планом; `bulk_in` совпал с приёмом.
4. Время ответа посчитано по меткам времени приёма (опрос порта ~20 мс), поэтому точность около 20 мс.

## Что не установлено

1. Что значит `<b7>` вообще. Значения `20` и `00` дали одинаковый результат по диапазону. Возможно, его биты — старшие биты cid; для cid больше 255 это не проверялось.
2. Роль sid. В кадрах sid равен cid.
3. cid вне диапазона. Не проверялся.
4. Условие запуска P1 не проверено до отправки: файл приёма занят скриптом. Модуль оказался в FM, как ожидалось, поэтому результат не пострадал.

## Предложение для whitelist

Строку добавляет только владелец. Проверены только FM cid 28 и 29. Вариантов три:

1. **Узкий.** playSelect в FM только для cid 28–29. Для приложения бесполезен.
2. **Весь FM без проверки границ.** cid 0–205 (по формуле 87,5–108,0 МГц), тот же лимит: не чаще 1 раза в 1 с, по действию пользователя, без автоповтора. Риск: границы диапазона и поведение Модуля у краёв не измерены.
3. **С проверкой границ (рекомендация агента).** Эксперимент G4-8: playSelect на FM cid 0 и 205 (края) и на AM cid 21 и 58 (края известного диапазона). После него строка охватывает FM целиком по измеренным границам.

Байт `<b7>` не задаёт диапазон, поэтому кадр может нести `20` в обоих диапазонах. Диапазон переключает только BAND.
Для AM действует строка G4-6: cid 21–58.
