# G4-2: одна отправка TUNEUP

Дата: 14 октября 2026 года. Уровень воздействия E: команды из [command-catalog.md](command-catalog.md) по решению владельца.
Сбор выполнил Claude Code в Windows по [g4-2-windows-plan.md](../plans/g4-2-windows-plan.md); анализ выполнен в WSL.

## Итог

TUNEUP (`80 88`) понизил частоту на один шаг: cid 58 → 57, «1044 KHz» → «1035 KHz».
Ожидалось повышение до 1053 кГц. Имя константы `Utils.TUNEUP` не совпадает с действием на Модуле.
Это согласуется с кодом производителя: TUNEUP шлёт обработчик `MainActivity.onPrevious`, TUNEDOWN — `onNext`. Подпись кнопок в ресурсах не проверялась.
Через 1,6 мс после TUNEUP пришёл один Кадр `0x22` с новой станцией. Связь выведена по времени, наблюдение одно.
Гипотеза AM «522 + 9 × cid» согласуется со второй точкой: 522 + 9 × 57 = 1035. Двум точкам подходит любая линейная модель, поэтому это по-прежнему гипотеза.
Модуль остался на 1035 кГц. Возврат на 1044 кГц — вероятно, `80 89` (TUNEDOWN по имени); он не в whitelist.

```text
18:51:45.6327 хост → requestAllInfo SEQ 0   +0,5…2,2 мс: 0x27, 0x22 cid 58 «1044 KHz», 0x24, 0x21
18:52:15.6047 хост → TUNEUP SEQ 1           +1,6 мс:     0x22 cid 57 «1035 KHz»
18:52:45.6038 хост → requestAllInfo SEQ 2   +0,6…2,2 мс: 0x27, 0x22 cid 57 «1035 KHz», 0x24, 0x21 «1044  KHz»
```

`0x22` до и после TUNEUP:

| Поле | До (SEQ 122) | После TUNEUP (SEQ 157) | После requestAllInfo (SEQ 191) |
|---|---|---|---|
| режим `(тело[1]>>5)&3` | 0 (AM) | 0 (AM) | 0 (AM) |
| cid | `00 3a` = 58 | `00 39` = 57 | `00 39` = 57 |
| текст | « 1044 KHz» | « 1035 KHz» | « 1035 KHz» |
| байт +30 | `0x16` | `0xf7` | `0x00` |
| байт +50 | `0xae` | `0x00` | `0xae` |

Смещения +30 и +50 отсчитаны от начала Кадра (`FA`), индекс `тело[1]` (байт +6 Кадра) — от байта типа. Байты +30 и +50 Приложение производителя не разбирает; смысл не установлен.
Список `0x21` после TUNEUP не изменился: одна запись cid 58 «1044  KHz». Список хранит станции, а не текущую частоту.
Сигнал `0x24` (байт +7 Кадра) = 3 до и после TUNEUP: на двух соседних каналах уровень одинаков.

## Наблюдения пользователя

Дословно: «небольшой нагрев модуля; звуков никаких нет».
Модуль был подключён к компьютеру без аудиотракта, поэтому отсутствие звуков ничего не говорит о радио.
Переподключения во время работы порта не было: `pnp-after.txt` (до отправок) и `pnp-after-tx.txt` совпадают побайтово, в трассе у Модуля один адрес.

## Попутные наблюдения

1. Первое подключение Модуля Windows не обнаружил; пользователь переподключил его, и COM5 появился. В трассе есть только второе подключение Модуля.
2. 116 байт потеряны до открытия порта. В 18:50:44.156, за 1,46 с до `Open()`, драйвер принял два пакета bulk IN: SEQ 0–4.
   Сразу за ними хост отправил `SET_CONTROL_LINE_STATE` 0. Приём начался с хвоста Кадра `0x23` (85 байт мусора) и SEQ 5.
   Кто прочитал данные, не установлено. `g4-2.ps1` запущен в 18:50:43.27, за 0,9 с до события; ранний доступ из скрипта не исключён. Это может быть и причиной обрывов на смещении 1229 в G1b и G4-1; гипотеза.
3. Потерянные Кадры SEQ 0–4 видны только в трассе: `0x26` «Mono», `0x27`, `0x28 00`, `0x24 01 64`, `0x23` из пробелов.
   `0x24` с байтом +6 = 1 по коду производителя — прогресс автопоиска; байт +7 = 100.
4. Модуль дважды прислал один и тот же пакет USB. Пакеты одинаковые и идут с разницей 0,2–0,3 мс:
   - 18:53:02.358 — SEQ 211 `0x29 00 04`;
   - 18:53:38.759 — SEQ 250 `0x26` и SEQ 251 `0x24`.
   В G1b и G4-1 повторов не было. Гипотеза по двум случаям: приём в приложении должен отбрасывать Кадр с тем же SEQ и телом, что и предыдущий.
5. `0x29` b7 по-прежнему циклически идёт 1…10 каждые 15 с.

## Статус

| Что | Статус |
|---|---|
| TUNEUP `80 88` | шаг частоты вниз на 9 кГц в AM; одно наблюдение |
| Имена констант | `TUNEUP` шлёт `onPrevious`: по коду и по эффекту. `TUNEDOWN` шлёт `onNext`: по коду, не проверено |
| Гипотеза AM 522 + 9 × cid | согласуется с двумя точками: 58 → 1044, 57 → 1035; гипотеза |
| Модель B для TX | согласуется: три отправки, SEQ 0, 1, 2 приняты |
| H06 (CDC управляет Модулем) | согласуется: после TUNEUP Модуль сообщил новую станцию. Одно наблюдение, связь по времени; нужен повтор, например `80 89` с возвратом на cid 58 |
| requestAllInfo | второй и третий ответ того же состава, 0,5–2,2 мс |
| Повторы пакетов Модулем | новое наблюдение, два случая; причина неизвестна |
