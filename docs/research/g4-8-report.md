# G4-8: границы cid у playSelect и уровень сигнала

Дата: 15 октября 2026 года. Уровень воздействия E: четыре кадра playSelect на краях диапазонов одобрены владельцем планом [g4-8-windows-plan.md](../plans/g4-8-windows-plan.md) (PR 52). Билет: [#33](https://github.com/krasotinpa/super-radio-android/issues/33).
Сбор выполнил Claude Code в WSL через Windows PowerShell; анализ — `research-tools/analyze_session.py`.

## Итог

Модуль принял все четыре кадра и ответил за 31–44 мс. Формула FM «МГц = 87,5 + 0,1 × cid» подтверждена на обоих краях: cid 0 → 87,5 МГц, cid 205 → 108,0 МГц.
В AM работают cid 21 («711 KHz») и 58 («1044 KHz»), формула «кГц = 522 + 9 × cid» подтверждена.
Побочных эффектов не видно: переподключения нет, `0x28` не приходил, звуков нет, нагрев и индикаторы в норме.
Байт +7 в `0x24` похож на уровень сигнала: у станции 5–6, на краях FM 3 и 0, в AM 0–1. Это наблюдение, не доказательство.
Каждый переход наблюдался один раз.

```text
Старт: FM cid 28 «90.3  MHz»
19:39:39 E1 FM cid 0     +44 мс: «87.5  MHz»
19:40:39 E2 FM cid 205   +31 мс: «108.0  MHz»
19:41:39 BAND            +266 мс: AM cid 31 «801 KHz»
19:42:39 E3 AM cid 21    +33 мс: «711 KHz»
19:43:39 E4 AM cid 58    +32 мс: «1044 KHz»
```

## Что подтверждено

| Кадр | Запрос | Ответ Модуля | Время |
|---|---|---|---|
| E1 | FM cid 0 | `0x22`: cid 0, «87.5  MHz» | 44 мс |
| E2 | FM cid 205 | `0x22`: cid 205, «108.0  MHz» | 31 мс |
| E3 | AM cid 21 | `0x22`: cid 21, «711 KHz» | 33 мс |
| E4 | AM cid 58 | `0x22`: cid 58, «1044 KHz» | 32 мс |

1. Модуль не прижал значения к границам: запрошенный cid вернулся без изменений.
2. Время посчитано по меткам времени приёма (опрос порта ~20 мс).
3. Скрипт проверял режим (FM/AM) по `0x22` перед каждым playSelect; проверка не сработала ни разу.
4. В трассе 11 пакетов bulk OUT; байты и порядок совпали с планом; `bulk_in` совпал с приёмом.
5. BAND из FM перевёл Модуль в AM cid 31 «801 KHz» — станцию, которую Модуль запомнил в G4-6. AM помнит свою последнюю станцию.

## Уровень сигнала (`0x24`, байт +7)

Значения из коротких Кадров `0x24` с b6 = 0, по состоянию станции:

| Состояние | Значения байта +7 (количество Кадров) |
|---|---|
| FM 90.3 MHz (cid 28, станция «ABTO») | 5 (48), 6 (10), 12 (1) |
| FM 87.5 MHz (cid 0) | 3 (31) |
| FM 108.0 MHz (cid 205) | 0 (31) |
| AM 801 KHz | 0 (21), 1 (11) |
| AM 711 KHz | 1 (31) |
| AM 1044 KHz | 0 (6), 1 (30) |

Ранее G1b показал, что `0x24` b7 меняется с антенной ([hardware-protocol-notes.md](hardware-protocol-notes.md)). Теперь значения согласуются с уровнем сигнала (станция — выше, край диапазона — ниже, на 108,0 — ноль). Но станция на 87,5 МГц неизвестна, шкала и максимум неизвестны (один раз 12), AM даёт 0–1 на всех частотах.
Показывать уровень пользователю нельзя без проверки: нужна запись сильной и пустой частоты рядом, с известной станцией на каждой.

## Что не установлено

1. Роль sid в кадре playSelect (в кадрах sid равен cid).
2. cid вне диапазона: ниже 0 невозможно, выше 205 в FM и вне 21–58 в AM не проверялись.
3. Шкала и смысл байта +7 `0x24` как уровня сигнала.
4. Влияние playSelect между границами (по пять-шесть значений проверено в G4-6–G4-8).

## Предложение для whitelist

Строку вносит только владелец. Проверены оба края обоих диапазонов, формулы подтверждены, поэтому агент предлагает:

| Команда | Кадр | Разрешено |
|---|---|---|
| playSelect (AM) | `FA 55 <SEQ> 00 07 80 82 20 <cid> 00 <cid> <сумма>` | не чаще 1 раза в 1 с, только по действию пользователя, без автоповтора; AM cid 21–58 |
| playSelect (FM) | то же | то же; FM cid 0–205 |

Диапазон переключает только BAND; `<b7>` = `20` в обоих диапазонах. Cid вне этих диапазонов запрещены.
