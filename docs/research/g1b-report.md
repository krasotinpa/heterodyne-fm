# G1b: пассивный приём и USB-трасса

Дата: 14 октября 2026 года. Уровень воздействия C: COM-порт открывался, в порт ничего не писалось.
Сбор выполнил Claude Code в Windows по [g1b-windows-plan.md](../plans/g1b-windows-plan.md); анализ выполнен в WSL.

## Итог

1. Хост не отправил Модулю ни одного байта данных: bulk OUT с данными — 0 пакетов в обоих сеансах.
2. Все Кадры обоих сеансов разбираются по модели B, суммы верны. Модель B подтверждена наблюдением RX.
3. SEQ начинается с 0 после подключения, растёт на 1 и после 253 переходит в 0. Значения 254 и 255 не встречаются.
4. Антенна меняет кадр `0x24`: без антенны b7 = 0, с антенной b7 = 3–4.
5. Модуль сам шлёт `0x26` и `0x24` каждые 2 с и `0x29` каждые 15 с. До открытия порта он копит Кадры и теряет их при переполнении.

```text
подключение ─▶ Модуль копит Кадры (SEQ с 0) ─▶ открытие порта: пачка накопленного
            ─▶ каждые 2 с: 0x26, 0x24 (сигнал) ─▶ каждые 15 с: 0x29 (b7 = 1…10 по кругу)
```

## Трафик Модуля в трассе

Трасса начинается до подключения, поэтому в неё попали перечисление и все запросы драйверов.

| Момент | Запросы к Модулю | Источник |
|---|---|---|
| Подключение | `GET_DESCRIPTOR`, `SET_CONFIGURATION 1`, `SET_INTERFACE` IF 1 alt 0 и IF 3 alt 0 | Windows |
| Подключение | `GET_CUR` Mute Feature Unit 2 (`a1 81 00 01 00 02 01 00`) | `usbaudio` |
| Подключение | `GET_LINE_CODING`, `SET_CONTROL_LINE_STATE` 0, `SET_LINE_CODING` 115200 8N1 | `usbser` |
| Открытие порта | за 6 мс: 6 × `SET_LINE_CODING` 115200 8N1, 3 × `SET_CONTROL_LINE_STATE` с RTS=1, затем RTS=0, 14 × `GET_LINE_CODING` | `usbser` по вызову .NET `SerialPort.Open` |
| Закрытие порта | 2 × `SET_CONTROL_LINE_STATE` 0 | `usbser` |

1. `SET_CONTROL_LINE_STATE` с `wValue 0x0002` значит RTS=1, DTR=0. Скрипт задавал `RtsEnable=false`. RTS был поднят около 3 мс.
2. Влияние короткого RTS=1 на Модуль оценить нельзя: без открытия порта Кадры не читаются, сравнения нет.
3. Endpoint прерываний `0x84` данных не прислал.
4. Bulk IN из трассы побайтно равен `rx.bin` в обоих сеансах: скрипт прочитал всё, что отправил Модуль.

### Стартовая пачка

Сразу после открытия порта приходят Кадры, накопленные с момента подключения. Их начало одинаково в A и B:

| SEQ | Тело | Разбор по [vendor-apk-analysis.md](vendor-apk-analysis.md) |
|---|---|---|
| 1, 6 | `27` + ASCII `V3.04.20250530` | текст MCU; похоже на версию прошивки |
| 2 | `28 00` | регион FM 0 |
| 3 | `24 01 64` | прогресс автопоиска 100 |
| 4 | `23 00` + пробелы | текст DAB, пустой |
| 5 | `21 c0` | список станций: флаги очистки и завершения, без записей |
| 7 | `22 00 3a ff ff ff …` | текущая станция: режим 0 (AM), cid `0x3a` = 58, sid `0xffff` |
| 8 | `24 00 0f` | сигнал 15 |
| 9 | `21 c0 00 3a 00 3a ff …` + `1044  KHz` | список: одна запись, cid 58, имя «1044  KHz» |
| 10 | `29 00 02` | `0x29`, b7 = 2 |

Гипотеза: cid AM — номер канала с шагом 9 кГц от 522 кГц, потому что 522 + 58 × 9 = 1044. Проверено на одной точке.

### Периодические Кадры

1. `0x26` и `0x24` приходят парой каждые 2,0 с (медиана 2001 мс, разброс 1963–2035 мс).
2. `0x26` всегда `26 04 00` + 16 пробелов: пустой текст состояния.
3. `0x29` приходит каждые 15 с. Его b7 идёт по кругу 1, 2, …, 10, 1. Смысл не установлен.

### Антенна

| Тело `0x24` после стартовой пачки | A | B |
|---|---|---|
| `24 00 00` | 175 | 0 |
| `24 00 03` | 0 | 1 |
| `24 00 04` | 0 | 167 |

В первой, прерванной сессии с антенной: `24 00 03` × 97, `24 00 04` × 59.
Это согласуется с разбором приложения производителя: при b6 = 0 байт b7 — уровень сигнала.

### Буфер Модуля

1. Первый bulk IN приходит в момент открытия порта и несёт Кадры с SEQ 0.
2. В A пачка за 56 с оборвана на Кадре SEQ 64: он отправлен частично, следующий пакет через 1,8 с начинается с SEQ 70.
3. Трасса показывает, что так отправил сам Модуль. Хост ничего не терял.
4. Гипотеза: Модуль копит около 1,2 КБ, пока порт закрыт, и при переполнении отбрасывает Кадры.
5. Скачок SEQ 0→57 в G0 согласуется с той же гипотезой: перед записью G0 порт открывался отдельно ([capture-method.md](../../evidence/capture-method.md)).

## Гипотезы

| ID | Статус после G1b |
|---|---|
| H01 | RX: 753 Кадра двух сеансов начинаются с `FA 55` и идут подряд без пропусков байт, кроме одного обрыва |
| H02 | RX: LEN = +3..+4 big-endian во всех Кадрах; длины 3, 4, 18, 20, 26, 66, 131 |
| H03 | RX: тип в +5 согласуется с периодичностью и с антенной (`0x24`) |
| H04 | RX: сумма тела равна 0 во всех 753 Кадрах |
| H05 | RX: SEQ — один байт, 0…253, затем 0; начинается с 0 после подключения |
| H06 | Управляет ли CDC радио, не проверялось: команд не было |
| H07 | Звук не проверялся |

Это экспериментальные наблюдения RX. TX и семантика команд по-прежнему не проверены на Модуле.

## Ограничения

1. Модуль, вероятно, был в режиме AM на 1044 кГц; FM не наблюдался.
2. Антенна — одна и в одном месте; уровни 3–4 не откалиброваны.
3. Время чтения в `reads.csv` отстаёт от прихода данных до ~20 мс опроса.
4. RTS=1 при открытии — поведение .NET и `usbser`; на Android последовательность запросов будет другой.

## Следующий шаг

Первая команда TX требует решения владельца. Кандидат — `requestAllInfo` (`80 85 07`).
Код приложения не показывает, какие Кадры придут в ответ. Ответ записывается как новое наблюдение, по одной отправке без повтора.
