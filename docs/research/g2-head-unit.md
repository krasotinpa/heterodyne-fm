# G2, часть 1: сведения о ГУ по фото

Дата: 15 октября 2026 года. Источник — 13 фото экранов ГУ и консоли, снятые пользователем.
Это historical observation по экранам настроек, а не опрос системы. По словам владельца, Модуль к ГУ не подключался.

## Итог

ГУ работает на Android 11 (API 30), модель G7PH-23MM. Сборка — `userdebug`, а не `user`.
Поверх заводской прошивки стоит русификация Titan-Auto TA-2.0.1; установлены RuStore и сторонние приложения.
На консоли два разъёма USB-C; по значкам левый — данные, правый — зарядка. У Модуля, со слов владельца, штекер USB-A: нужен переходник.
ABI, версия ядра, поддержка USB host и USB-аудио по фото не устанавливаются.

## Процессор и память по открытым источникам

Поиск 15 октября 2026 года по модели G7PH-23MM и строке `g7pa_23mm` ничего не дал: в открытых источниках этих обозначений нет.
По модели автомобиля нашлось следующее:

1. Китайские обзоры Highlander 2026 модельного года от GAC Toyota пишут, что ГУ построено на Qualcomm Snapdragon 8155P (SA8155P), экран 15,6 дюйма.
   Источники — автомобильные блоги на Autohome и Weibo, а не официальная спецификация. Модель ГУ в них не названа.
   Примеры: [Autohome 23347438](https://chejiahao.m.autohome.com.cn/info/23347438), [Autohome 22209508](https://chejiahao.autohome.com.cn/info/22209508).
2. Объём памяти для Highlander не найден. Для Camry девятого поколения от GAC Toyota с тем же чипом 8155 IT之家 пишет 12 ГБ ОЗУ и 128 ГБ памяти ([ithome 742760](https://www.ithome.com/0/742/760.htm)).
   Перенос этих цифр на Highlander — гипотеза.
3. SA8155P — 64-битный процессор Arm. Ожидаемый ABI — `arm64-v8a`. Гипотеза до опроса системы.

Что ГУ этого автомобиля — именно на 8155P, подтвердит диагностическое приложение: `Build.HARDWARE`, `Build.BOARD`, `/proc/cpuinfo`, `Build.SUPPORTED_ABIS`, объём памяти.
Связь сборки `g7pa_23mm` с 8155P не установлена.

1. Системные: Навигация, Настройки, Carlink, Apple CarPlay, HUAWEI HiCar, Ассистент, «Кнопка», Календарь, Радио, USB, BT-Музыка, Телефон, Менеджер, RuStore, Сцены.
2. Дополнительные: FMPLAY, RUTUBE, Яндекс Навигатор, Яндекс Музыка, VK Видео, PCRadio, Яндекс Браузер, 2ГИС, HUD Speed, Radio (синяя иконка), Кинопоиск.
3. В разрешениях также видны «Медиа-площадка», `地图` (карты), WebView Shell.

RuStore и сторонние приложения установлены: возможна установка из магазина или предустановка надстройкой. Установка APK файлом с SSD не установлена.
Пункт «Неизвестные источники» на фото не попал.
По словам владельца, FMPLAY играет интернет-радио; PCRadio не работает, потому что в ГУ нет FM-модуля. Приложение Radio (синяя иконка) не опознано.
Встроенное «Радио» — вероятно, штатный тюнер автомобиля и с Модулем не связано. Гипотеза.

## USB

У владельца есть переходник OTG USB Type-C.

На консоли под подлокотником два разъёма USB-C:

| Разъём | Значок | Назначение |
|---|---|---|
| Левый | USB (трезубец) | по значку — данные; вероятно, CarPlay, HiCar, USB-музыка и «Обновление USB» |
| Правый | батарея с молнией | по значку — только зарядка |

У Модуля штекер USB-A. Для подключения нужен переходник USB-C (папа) → USB-A (мама) с передачей данных, либо хаб с USB-C.
Работает ли левый разъём как USB host для произвольного устройства, по фото не установлено: это первый вопрос G2.
Ток питания разъёма неизвестен. Нагрев Модуля не измерялся; пользователь описывал его как слабый.

## Что это значит для приложения

1. API 30 известен: `minSdk` ≤ 30. ABI нужен, если звук пойдёт через нативный изохронный приём (libusb); для чистого Kotlin/Java — нет. Toolchain закрепить после определения ABI.
2. В Android 11 есть USB host API, но ГУ может не объявлять `android.hardware.usb.host`. Видит ли ГУ Модуль и выдаёт ли разрешение, проверит только подключение.
3. Звук — возможно через систему: если ядро и аудио-HAL ГУ принимают UAC1-вход Модуля, он появится как `AudioDeviceInfo.TYPE_USB_DEVICE`.
   Тогда его можно читать через `AudioRecord` с разрешением `RECORD_AUDIO` и выбором устройства. Иначе нужен свой изохронный приём через libusb, как в Приложении производителя.
   То, что производитель выбрал libusb, не доказывает, что системный путь не работает. Это развилка ADR; решается измерением на ГУ.
4. Сборка `userdebug` может дать ADB и `logcat`. Это сильно упростит G2, но требует включить отладку — решение владельца.

## Не установлено

Пункты 1 (ABI и платформа `msmnile`), 2, 4 и 5 закрыты опросом системы: см. [g2-probe-report.md](g2-probe-report.md). Маркировка чипа не подтверждена.

1. ABI и процессор: по открытым источникам — SA8155P и `arm64-v8a`; опросом системы не подтверждено.
2. Версия ядра и уровень патча безопасности: на фото их нет.
3. Есть ли «Неизвестные источники» и «Параметры разработчика».
4. Работает ли разъём данных как USB host для Модуля.
5. Есть ли в системе USB-аудио вход.
