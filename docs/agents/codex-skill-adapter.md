# Адаптер инструкций Skills для Codex

Применяй этот документ, если выбранный скилл ссылается на отсутствующий интерфейс другого агента.
Проектные правила и прямые указания владельца сохраняют приоритет.

| Ссылка в универсальной инструкции | Действие в Codex |
|---|---|
| `Call the Skill tool with X` | Найди X в каталоге сессии, прочитай его SKILL.md и примени процесс через доступные инструменты |
| `Read` / `Bash` | Используй доступное чтение файлов и исполнение команд Codex в фактическом sandbox |
| `Task` / `Agent` / sub-agent | Используй родной механизм Codex только когда делегирование предусмотрено задачей, скиллом или проектным процессом |
| `GLOSSARY.md` / `GLOSSARY-MAP.md` | Используй CONTEXT.md и docs/adr/ по [доменным правилам](domain.md); не создавай второй словарь |
| Общее указание `graphify` для поиска | Используй проектный heterodyne-graphify и его исключение для чтения |
| `claude --bg`, Claude hooks, Companion | Не запускай как часть процесса Codex; эти сценарии исключены из активного набора проекта |

Чтение файла ради аудита не доказывает применение процесса. Не имитируй вызов отсутствующего инструмента или его результат.
Если нужный скилл недоступен, сообщи причину и действуй по правилам AGENTS.md; не объявляй его успешно использованным.
Metadata `allowed-tools`, `context: fork` и названия инструментов не задают фактические права Codex.
Разрешения определяет среда выполнения, а действия — задача и проектные ограничения.

## Реализация и review

Один исполнитель реализует связный блок. Общий `implement-spec` не разрешает автоматически запустить параллельных исполнителей.
Для code-review нужны два независимых Codex reviewer: Standards и Spec.
Передай им base/head, весь diff, новые файлы, задачу и результаты gate по [процессу](codex-implementation.md#независимое-review).
Используй свежие контексты. Reviewer только читают, исполнитель оценивает findings и исправляет их одним пакетом.
Если родное независимое review недоступно, сообщи ограничение; самопроверка не заменяет независимых reviewer.

Используй уже заданные задачей и test-plan границы проверок и известную базу PR.
Не запрашивай их повторно только из-за отсутствия буквального `Skill` tool.
Если существенная граница действительно не определена, уточни её до зависимых изменений.

В `implement`, псевдонимах grilling и handoff полезные инструкции можно прочитать отдельно при явной задаче.
Они не заменяют ветку-worktree, test-first, local gate, review и пределы полномочий проекта.
Для обычного продолжения работы используй штатную сессию Codex и инструкции проекта, без цепочки оркестраторов.
