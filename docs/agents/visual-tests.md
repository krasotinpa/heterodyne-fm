# Технические визуальные проверки

`VisualRegressionTest` передаёт фиксированные снимки UI Contract в `RadioSnapshot`.
Тесты используют Robolectric 4.16.1 native graphics на Linux x86_64, JDK 17 и Android API 35.
Конфигурация задаёт `ru-RU`, альбомную ориентацию, mdpi (160 dpi) и палитру Coral.
Шрифты Golos Text и JetBrains Mono входят в ресурсы приложения. Системные резервные шрифты поставляет образ API 35.
Тесты начинают часы Robolectric с фиксированного значения и снимают статические состояния после синхронизации Compose.
Перед снимком формы тест снимает фокус с поля, чтобы исключить мигающий курсор.
Данные станций, версия приложения и результат экспорта заданы в тесте. Обработчики действий пустые.

Полный `./build-support/validate.sh` включает эти проверки. Запусти их отдельно из корня worktree следующей командой.

```bash
./gradlew :ui-compose:testDebugUnitTest --rerun \
  --tests '*VisualRegressionTest' --tests '*HiddenActionsSemanticsTest'
```

## Матрица эталонов

В каждой ячейке указан сценарий для сочетания разрешения, Темы и масштаба.
[Каталог PNG](../../ui-compose/src/test/resources/screenshots/) содержит 14 эталонов для 12 сочетаний.

| Размер | Светлая 1,0 | Тёмная 1,0 | Светлая 1,3 | Тёмная 1,3 |
| --- | --- | --- | --- | --- |
| 1024×600 | Эфир | Меню Стоянки | Ошибка частоты, отключённый Приёмник в Эфире | Ошибка частоты, Эфир |
| 1280×720 | Эфир с пустой Подборкой | Эфир с пустой Подборкой | Диагностика | Эфир |
| 1920×1080 | Редактор Подборки | Диагностика | Меню Стоянки | Эфир |

`HiddenActionsSemanticsTest` проверяет дерево действий Compose отдельно от PNG.
Поиск уходит из дерева доступности на ходу. У Приёмника без Поиска действия отсутствуют и в необъединённом дереве.
Пункт «Режим разработчика» исчезает из обоих деревьев после выключения режима.

## Разбор расхождения

Тест сравнивает точные значения пикселей через `Bitmap.sameAs`.
При расхождении тест пишет `*-actual.png` и `*-diff.png` в `ui-compose/build/reports/screenshots/`.
Если проверка или действие Compose завершается ошибкой, тест сохраняет последний кадр и выводит исходную причину.
Пурпурные пиксели diff отмечают различия. Прозрачные пиксели совпадают.
Имя отчёта содержит сценарий, разрешение, Тему, масштаб и API. Сообщение теста добавляет locale и плотность.
Если эталон отсутствует, тест сохраняет только фактический снимок.
При падении Android job CI сохраняет этот каталог в артефакте `screenshot-failures` на 7 дней.

Проверь путь отказа в локальном worktree с эталонами. Команда временно подменяет светлый эталон ошибки частоты тёмным.

```bash
(
  set -e
  unset HETERODYNE_RECORD_SCREENSHOTS
  refs=ui-compose/src/test/resources/screenshots
  target="$refs/frequency-error-1024x600-light-1.3.png"
  backup=$(mktemp)
  cp "$target" "$backup"
  trap 'cp "$backup" "$target"; rm -f "$backup"' EXIT
  cp "$refs/frequency-error-1024x600-dark-1.3.png" "$target"
  ./gradlew :ui-compose:testDebugUnitTest \
    --tests '*VisualRegressionTest.compactLightFrequencyErrorMatchesReference'
)
```

Ожидаемый код Gradle — 1. Проверь пару `frequency-error-1024x600-light-1.3-api35-{actual,diff}.png`.
После восстановления эталона повтори обычный запуск и проверь код 0.

## Намеренное обновление эталонов

1. Проверь причину изменения UI и версии среды.
2. Запиши эталоны локально. Для одного сценария укажи имя его теста после `--tests`.
3. Открой каждый обновлённый PNG. Проверь читаемость, обрезание, перекрытие и ожидаемое состояние.
4. Запусти команду проверки выше без флага записи. Проверь изменения PNG в PR.

```bash
HETERODYNE_RECORD_SCREENSHOTS=1 ./gradlew :ui-compose:testDebugUnitTest \
  --tests '*VisualRegressionTest' --rerun-tasks
```

CI запрещает запись эталонов. Указанные флаги `--rerun-tasks` и `--rerun` принудительно запускают тест, когда меняется только переменная среды.
Снимки фиксируют текущий рендеринг. Наблюдения и известные дефекты перечислены в [отчёте #327](../validation/issue-327.md).
Визуальную приёмку штатного ГУ проводит владелец.

```text
Снимок UI Contract → Compose → View.draw → Bitmap.sameAs
                                      ├─ совпало → тест прошёл
                                      └─ разошлось → actual PNG + diff PNG
```

## Визуальный прогон Run 4

Собери APK, создай паспорт и подготовь новый AVD по [инструкции runner](run4-preflight-apk.md#сквозной-runner-abcx).
В той же команде укажи `run visual` вместо `run android-ui` и убери `--https`.
Runner проверит APK и принадлежность стенда, затем запустит 12 сочетаний в одном AVD.
Разрешения 1280×720, 1024×600 и 1920×1080 получают плотность mdpi, оба масштаба 1,0 и 1,3 и обе темы.

Instrumentation вызывает Android `screencap` на каждом экране, пока он открыт. Runner забирает оригиналы через отдельный ADB.
У каждого прогона свой гостевой каталог. Runner сверяет начало и конец PNG и его размеры.
В `report.json` записываются параметры стенда, размеры и SHA-256 каждого PNG.
Статус `captured` означает полный захват, а `visual_review: pending` оставляет оценку изображений агенту.
Просмотри все PNG. Сверь читаемость, обрезание, перекрытие и наличие ожидаемого состояния.
Открой оригинал в полном размере для оценки мелкого текста или спорного места.
Запиши проблемные сочетания и пути к снимкам. Дубликаты проверяй через `gh`.
Сохрани отдельный итоговый `reviewed-report.json` с SHA исходного отчёта, результатом осмотра и ссылками Issues.

Прогон снимает «Эфир», меню стоянки, «Настройки», «Регионы», «Подборки», «Диагностику» и «О приложении».
Он также снимает ошибку частоты и синтетическую ошибку обновления Справочника.
Для кадра ошибки частоты Compose вызывает действие сохранения через семантику элемента. Доступность кнопки оценивай по PNG отдельно.
Результаты и ограничения записывай в [отчёт блока 4](../validation/run4-preflight-block4.md).
