# Временная пауза GitHub CI

Владелец отключил CI 16.11.2026 на время изменения среды разработки.
Причина: текущие задачи меняют настройки и документацию, а не код приложения.
Владелец также разрешил временно снять обязательность `python` и `android` для merge.
После завершения изменения среды восстанови workflow и обязательность проверок.
Merge выполняется по [полномочиям AGENTS.md](../../AGENTS.md#полномочия), включая временное разрешение Codex для 14 пунктов среды.

## Текущее состояние

| Настройка | Состояние |
|---|---|
| Workflow `CI`, `.github/workflows/ci.yml`, ID `386827376` | `disabled_manually` |
| Ruleset для `main`, ID `25250346` | `active` |
| Требование успешных `python` и `android` | Временно удалено из ruleset |
| Требование PR, запрет удаления и force push | Сохранены без изменения |

Запуск `43930330673` отменён по решению владельца.
В нём `python` завершился успешно, а `android` получил `CANCELLED`.
Это отменённая проверка, а не доказанная ошибка Android-сборки.
Workflow-файл и локальные критерии проверок не менялись.
Пауза не отменяет test-first, local validation gate и независимое review по [процессу Codex](codex-implementation.md).

## Восстановление после изменения среды

1. Получи актуальный ruleset через `gh api repos/krasotinpa/heterodyne-fm/rulesets/25250346`.
2. Добавь правило ниже, сохранив остальные актуальные правила, условия и исключения.
3. Сохрани изменённые данные через `PUT` того же API и проверь фактический ответ повторным чтением.
4. Выполни `gh workflow enable ci.yml --repo krasotinpa/heterodyne-fm`.
5. Проверь активность workflow и наличие обязательных `python` и `android`.
6. Отправь коммит завершения работ в feature-ветку; новый push должен запустить CI для актуального head PR.
7. Дождись успешных результатов обеих проверок перед merge и обнови этот документ.

```json
{
  "type": "required_status_checks",
  "parameters": {
    "strict_required_status_checks_policy": false,
    "do_not_enforce_on_create": false,
    "required_status_checks": [
      {"context": "python", "integration_id": 15368},
      {"context": "android", "integration_id": 15368}
    ]
  }
}
```

Если такое правило уже есть, сравни его с сохранённым состоянием и не затирай чужие изменения.
При `PUT` передай актуальные `name`, `target`, `enforcement`, `conditions`, `bypass_actors` и `rules`.
Полная резервная копия исходного ruleset хранится локально в игнорируемой `.scratch/` рабочего дерева PR #293.
Не применяй старую полную копию поверх будущих изменений ruleset.
Этот JSON сохраняет только удалённое требование CI; его достаточно для точечного восстановления.

```text
Завершение изменения среды → восстановление ruleset → включение workflow
                          → новый push → python + android → merge по полномочиям
```
