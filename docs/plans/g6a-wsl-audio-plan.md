# G6a: звук Модуля через WSL и USB/IP

Стендовый опыт на ноутбуке, не в автомобиле. Уровень воздействия: стандартные запросы драйверов Linux к звуковому интерфейсу Модуля.
Радиокоманд нет, CDC-порт не открывается и не получает драйвера. Перед началом прочитаны [safe-capture-guide.md](../safe-capture-guide.md) и [descriptor-map.md](../research/descriptor-map.md).

Цель — до проверки на ГУ узнать:

1. Принимает ли драйвер Linux `snd-usb-audio` звуковой интерфейс Модуля с его ошибкой в дескрипторе.
2. Отдаёт ли Модуль звук без радиокоманд.
3. Каковы формат и качество потока.

На ГУ работает то же семейство драйверов, но ядро старше, а звук может идти и через `libUSBAudio.so`. Поэтому результат — признак для выбора пути, не прогноз для ГУ.

```text
Модуль ── USB ── Windows (usbipd-win) ── USB/IP ── WSL: vhci_hcd → snd-usb-audio → ALSA → arecord → WAV
                                                         └→ usbmon: журнал USB-запросов
```

## Исполнители

| Кто | Где | Что делает |
|---|---|---|
| Владелец | Windows: PowerShell; от администратора — только установка и `bind` | ставит usbipd-win, подключает и пробрасывает Модуль, слушает WAV |
| Агент | WSL `Ubuntu`, этот репозиторий | готовит WSL, пишет журналы, записывает и разбирает звук |

## Границы

1. Радиокоманды не отправляются. Драйвер `cdc_acm` заблокирован до подключения, поэтому `/dev/ttyACM*` не появляется.
   Блокировка нужна вдвойне: Union в дескрипторе Модуля указывает на IF 0–1, и `cdc_acm` мог бы захватить звуковой интерфейс 1.
2. Запросы к Модулю шлют только ядро и `snd-usb-audio`: перечисление, выбор alt setting, запросы класса UAC1 к блокам из дескриптора Модуля (`GET_*` и `SET_CUR`, частота, Mute).
   После опыта агент проверяет это по `usbmon`: ни одного запроса к IF 2–3 и ни одного vendor-запроса (`bmRequestType` 0x40/0xC0/0x41/0xC1).
3. Пока Модуль проброшен в WSL, Windows его не видит. USBPcap в этой сессии не нужен.
4. Громкость при прослушивании WAV — низкая.
5. Стоп-условия: Модуль циклически переподключается; `dmesg` сыплет ошибками без остановки; заметный нагрев; появился `/dev/ttyACM*`; `arecord` не завершился за 60 с.
   Агент сам отключить Модуль не может: он сразу просит владельца выполнить «Завершение».

Оригиналы — в `raw/g6a/<сессия>/`, в репозиторий не идут. Публичные копии журналов — в `evidence/g6a-<сессия>/` после редактирования:

- серийный номер Модуля → `<redacted-module-serial>`, в том числе в `usbmon.txt`, где он лежит байтами UTF-16LE строкового дескриптора;
- имя компьютера и пользователя → `<redacted-host>`, `<redacted-user>`;
- после замены скрипт ищет серийный номер в ASCII, в UTF-16LE и в hex с пробелами; находок быть не должно.

WAV не публикуется: это запись эфира. В отчёт идут длительность, формат, уровни и SHA-256. Для каждого файла в отчёте — пара SHA-256: оригинал и публичная копия.

## Подготовка

### Владелец, один раз

1. PowerShell от администратора: `winget install --exact --id dorssel.usbipd-win`. Перезапусти PowerShell.
2. `usbipd --version` — пришли вывод агенту. Нужна версия 4 или новее.
3. Закрой программы, которые пишут звук: Teams, «Запись голоса» и подобные.

### Агент

1. Проверь репозиторий, ветку и SHA. Создай `raw/g6a/<UTC-время>/` и `action-log.md`; каждое действие — строка с UTC.
2. `sudo apt-get install -y alsa-utils usbutils`; запиши `arecord --version` и `lsusb --version`.
3. Заблокируй `cdc_acm`: `echo 'install cdc_acm /bin/false' | sudo tee /etc/modprobe.d/g6a-block-cdc-acm.conf`.
   Проверь: `sudo modprobe cdc_acm` должен завершиться ошибкой; `lsmod | grep cdc_acm` пуст. Запиши оба результата.
4. Загрузи модули: `sudo modprobe vhci_hcd`, `sudo modprobe usbmon`, `sudo modprobe snd-usb-audio`. Запиши exit code каждого.
   Если модуль не найден — стоп: опыт требует другого ядра WSL.
5. Проверь `ls /sys/kernel/debug/usb/usbmon/`. Если пусто: `sudo mount -t debugfs none /sys/kernel/debug`.
6. Запусти журналы в фоне (`run_in_background`):
   - `sudo dmesg -w --time-format iso > dmesg.txt`;
   - `sudo cat /sys/kernel/debug/usb/usbmon/0u > usbmon.txt`.
   `0u` пишет все шины; Модуль потом выделяется по номеру шины и адресу. Текстовый usbmon обрезает данные до 32 байт: запросы видны полностью, звук — нет.
7. Сними до подключения: `arecord -l`, `cat /proc/asound/cards`.

## Шаги

1. Владелец: подключи антенну к Модулю, Модуль — к ноутбуку. Модуль питается от USB.
2. Владелец: открой окно WSL `Ubuntu`, если оно закрыто. В PowerShell выполни `usbipd list`.
   Пришли агенту строку Модуля. Пример вида: `2-4    0483:5740  Составное USB устройство, ...   Not shared`.
3. Владелец: PowerShell от администратора — `usbipd bind --busid <BUSID>`. Состояние в `usbipd list` станет `Shared`.
   Если usbipd просит `--force`, не используй его: пришли текст ошибки агенту.
4. Владелец: обычный PowerShell — `usbipd attach --wsl Ubuntu --busid <BUSID>`. Состояние станет `Attached`. Пришли вывод.
   Устройство записи Модуля в «Звук → Запись» Windows при этом пропадёт; это ожидаемо.
5. Агент: подожди 5 с и сними:
   - `lsusb -d 0483:5740`, `sudo lsusb -v -d 0483:5740 > lsusb.txt`;
   - `lsmod | grep -E 'usbmon|snd_usb_audio|cdc_acm|vhci'`, `ls /dev/ttyACM* /dev/snd`;
   - `arecord -l`, `cat /proc/asound/cards`, `cat /proc/asound/card<C>/stream0`, если карта есть;
   - `amixer -c <C> controls`: каких элементов нет.
6. Агент: если карты Модуля нет, выпиши из `dmesg.txt` все сообщения `usb`, `snd-usb-audio`, `uac`, `mixer`.
   Если причина — ошибка mixer, повтори один раз как отдельный опыт: `sudo modprobe -r snd-usb-audio`, `sudo modprobe snd-usb-audio ignore_ctl_error=1`,
   затем владелец делает `usbipd detach` и снова `attach`. Запиши, появилась ли карта.
7. Агент: если карта есть (карта `<C>`, устройство `<D>` из `arecord -l`):
   1. `arecord -D hw:<C>,<D> --dump-hw-params -d 1 -t raw /dev/null` — что поддерживает поток.
   2. `timeout 60 arecord -v -D hw:<C>,<D> -t wav -f S16_LE -r 48000 -c 2 -d 30 g6a.wav`. Запиши exit code, вывод и строки `overrun`.
   3. Если `hw` отказывает в формате — `plughw:<C>,<D>`, и запиши, что изменилось.
8. Агент: разбери WAV скриптом на stdlib (`wave`, `array`, без `audioop`) в `.scratch/`; скрипт в PR не входит, вывод — в отчёт.
   Показатели: число отсчётов против 48 000 × 30, пиковый и среднеквадратичный уровень по каналам, доля нулей, участки тишины длиннее 50 мс.
9. Агент: скопируй WAV в `.scratch/g6a.wav` и дай владельцу путь `\\wsl.localhost\Ubuntu\home\user\sources\super-radio-android\.scratch\g6a.wav`.
   Владелец слушает на малой громкости. Агент записывает ответ дословно: слышна ли станция, шум, щелчки.

## Завершение

1. Владелец: `usbipd detach --busid <BUSID>`. Чтобы вернуть Модуль Windows полностью: `usbipd unbind --busid <BUSID>`.
   Если USB/IP оборвался сам, повторный `attach` — только по решению агента, с записью в журнал.
2. Агент: останови фоновые журналы. Удали блокировку: `sudo rm /etc/modprobe.d/g6a-block-cdc-acm.conf`. Запиши это.
3. Агент: проверка `usbmon` по границе 2 — таблица всех управляющих запросов к Модулю: стандартные, класса UAC1, прочие. Прочих быть не должно.
4. Агент: SHA-256 всех оригиналов в `SHA256SUMS.txt`; редактированные копии; отчёт `docs/research/g6a-report.md`; PR.

## Что ищем

| Наблюдение | Вывод |
|---|---|
| Карта есть, WAV со звуком станции | Системный путь в Linux работает. На ГУ проверить `AudioRecord` с `TYPE_USB_DEVICE` |
| Карта есть, в `dmesg` предупреждения о терминале или mixer | Поток разобран, элементы управления — нет. Записать, каких нет; на звук это может не влиять |
| Карта есть, WAV — тишина или нули | Драйвер принял интерфейс. Причины: Модулю нужна команда или выбор источника, тюнер не настроен, слабый сигнал. Командой не проверять без решения владельца |
| Карты нет, любая ошибка разбора дескрипторов | Linux не принимает интерфейс как есть. Для ГУ это не прогноз: сравнить с разбором в `libUSBAudio.so`; кандидат — свой приём через libusb |
| Пропуски и щелчки, `overrun` | Вероятно, USB/IP; на ГУ проверить отдельно |

Качество считается приемлемым для следующего шага, если отсчётов не меньше 99 % от ожидаемых и нет участков нулей длиннее 50 мс.
Запросы `usbmon` сравниваются с тем, что шлёт драйвер производителя (`set_sample_rate_v1`).
