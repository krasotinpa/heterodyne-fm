# G6a: звук Модуля через WSL и USB/IP

Уровень воздействия: стандартные запросы драйверов Linux к звуковому интерфейсу Модуля. Радиокоманд нет, CDC-порт не открывается.
Цель — до проверки на ГУ узнать:

1. Принимает ли драйвер Linux `snd-usb-audio` звуковой интерфейс Модуля с его ошибкой в дескрипторе.
2. Отдаёт ли Модуль звук без радиокоманд.
3. Каковы формат и качество потока.

На ГУ работает то же семейство драйверов, поэтому результат — сильный признак для выбора пути звука. Гарантии он не даёт: ядро ГУ старше.
Проверено заранее: ядро WSL `6.18.40.1-microsoft-standard-WSL2` собрано с `CONFIG_SND_USB_AUDIO=m`, `CONFIG_USBIP_VHCI_HCD=m`, `CONFIG_USB_MON=m`.

```text
Модуль ── USB ── Windows (usbipd-win) ── USB/IP ── WSL: vhci_hcd → snd-usb-audio → ALSA → arecord → WAV
                                                         └→ usbmon: журнал USB-запросов
```

## Исполнители

| Кто | Где | Что делает |
|---|---|---|
| Владелец | Windows, PowerShell от администратора | ставит usbipd-win, подключает и пробрасывает Модуль |
| Агент | WSL Ubuntu, этот репозиторий | готовит WSL, пишет журналы, записывает и разбирает звук |

## Границы

1. Радиокоманды не отправляются. CDC-порт (`/dev/ttyACM*`) не открывается никем. Модуль `cdc_acm` агент не загружает.
2. Запросы к Модулю шлют только ядро и `snd-usb-audio`: стандартные запросы перечисления, выбор alt setting, запросы класса UAC1 (частота, Mute). Всё это пишет `usbmon`.
3. Пока Модуль проброшен в WSL, Windows его не видит. USBPcap в этой сессии не нужен.
4. Громкость при прослушивании WAV — низкая.
5. Стоп-условия: Модуль циклически переподключается, `dmesg` сыплет ошибками без остановки, заметный нагрев, неизвестное устройство вместо Модуля. Тогда агент просит владельца выполнить шаг «Завершение».

Оригиналы — в `raw/g6a/<сессия>/`. В `lsusb`, `dmesg` и `usbmon` есть серийный номер Модуля, поэтому в репозиторий они идут только с заменой на `<redacted-module-serial>`.
WAV не публикуется: это запись эфира. В отчёт идут длительность, формат, уровни и SHA-256.

## Подготовка

### Владелец, один раз

1. PowerShell от администратора: `winget install --exact dorssel.usbipd-win`. Перезапусти PowerShell.
2. `usbipd --version` — пришли вывод агенту.

### Агент

1. Проверь репозиторий, ветку, SHA; создай `raw/g6a/<UTC-время>/` и `action-log.md`. Каждое действие — строка с UTC.
2. `sudo apt-get install -y alsa-utils`; запиши версию `arecord --version`.
3. `sudo modprobe usbmon`, `sudo modprobe snd-usb-audio`; запиши `lsmod | grep -E 'usbmon|snd_usb_audio|cdc_acm|vhci'`.
4. Запусти журналы в фоне:
   - `sudo dmesg -w > dmesg.txt`;
   - `sudo cat /sys/kernel/debug/usb/usbmon/0u > usbmon.txt`.
5. Сними `arecord -l` и `cat /proc/asound/cards` до подключения.

## Шаги

1. Владелец: подключи антенну к Модулю, Модуль — к ноутбуку.
2. Владелец: `usbipd list`. Пришли агенту строку с `0483:5740` и её BUSID.
3. Владелец: `usbipd bind --busid <BUSID>`, затем `usbipd attach --wsl --busid <BUSID>`. Пришли вывод.
4. Агент: подожди 5 с и сними:
   - `lsusb -d 0483:5740` и `sudo lsusb -v -d 0483:5740 > lsusb.txt`;
   - `arecord -l`, `cat /proc/asound/cards`, `ls /dev/snd`;
   - `lsmod` по шаблону из подготовки: загрузился ли `cdc_acm` сам.
   Если загрузился, запиши это в журнал и не открывай `/dev/ttyACM*`.
5. Агент: если карты Модуля нет, выпиши из `dmesg.txt` сообщения `usb`, `snd-usb-audio`, `uac`. Это результат «драйвер не принял»; переходи к завершению.
6. Агент: если карта есть (номер `<C>`), запиши 30 с:
   `arecord -D hw:<C>,0 -f S16_LE -r 48000 -c 2 -d 30 g6a.wav`. Запиши exit code и вывод.
   Если `hw` отказывает в формате, попробуй `plughw:<C>,0` и запиши, что изменилось.
7. Агент: разбери WAV скриптом на stdlib: длительность, число отсчётов, пиковый и среднеквадратичный уровень по каналам, доля нулевых отсчётов, длинные участки тишины.
8. Владелец: прослушай `g6a.wav` на ноутбуке на малой громкости. Агент записывает ответ дословно: слышна ли станция, шум, щелчки.

## Завершение

1. Владелец: `usbipd detach --busid <BUSID>`. Чтобы вернуть Модуль Windows полностью: `usbipd unbind --busid <BUSID>`.
2. Агент: останови фоновые журналы, сними `dmesg` после отключения, посчитай SHA-256 всех файлов в `SHA256SUMS.txt`.
3. Агент: отчёт `docs/research/g6a-report.md`, редактированные копии журналов в `evidence/g6a-<сессия>/`, PR.

## Что ищем

| Наблюдение | Вывод для ГУ |
|---|---|
| Карта есть, WAV со звуком станции | Системный путь возможен: на ГУ проверить `AudioRecord` с `TYPE_USB_DEVICE` |
| Карта есть, WAV — тишина или нули | Драйвер принял интерфейс; Модулю, возможно, нужна команда или другой запрос. Сравнить с запросами `libUSBAudio.so` |
| Карты нет, в `dmesg` ошибка разбора терминала | Системный путь вряд ли сработает и на ГУ; основной кандидат — свой приём через libusb |
| Пропуски и щелчки | Вероятно, USB/IP; на ГУ проверить отдельно |

Сравнение запросов из `usbmon` с запросами драйвера производителя (`set_sample_rate_v1`) — часть отчёта.
