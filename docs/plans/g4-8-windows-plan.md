# G4-8: границы cid у playSelect

Исполнитель — Claude Code в Windows (через Windows PowerShell). Уровень воздействия E. Билет: создаётся после merge этого плана.
Цель — измерить, как Модуль отвечает на playSelect у краёв диапазонов, и получить границы cid для whitelist. Предыдущий опыт — [g4-6-report.md](../research/g4-6-report.md) и [g4-7-report.md](../research/g4-7-report.md).
Владелец 15.10.2026 выбрал вариант «с проверкой границ» (вариант 3 в g4-7-report). Параметры ниже вступают в силу после merge этого плана владельцем.
Кадры вне текущего whitelist. Они разрешены только как кадры этого эксперимента, по одной сессии.

## Кадры

| Кадр | Диапазон | Что проверяет |
|---|---|---|
| E1: cid 0 | FM | Нижний край. Формула даёт 87,5 МГц |
| E2: cid 205 | FM | Верхний край. Формула даёт 108,0 МГц |
| E3: cid 21 | AM | Нижний край проверенного диапазона: 711 кГц |
| E4: cid 58 | AM | Верхний край проверенного диапазона: 1044 кГц (станция из G4-2) |

Ожидание: `0x22` с запрошенным cid и частотой по формулам. Допустимые альтернативы: молчание, другой cid (Модуль прижал значение к границе), `0x28`, смена диапазона. Агент записывает любой ответ как есть и не повторяет кадры.
BAND в расписании один раз: он переводит Модуль из FM в AM между парами.

## Условие запуска playSelect

G4-7 показал, что файл приёма занят скриптом: агент не может прочитать ответ на лету. Поэтому проверку делает сам скрипт.
Скрипт ведёт буфер принятых байтов и помнит режим из последнего `0x22`: `(тело[1] >> 5) & 3` (FM = 1, AM = 0). Он проверен на разорванных кадрах отдельным тестом на ПК.
Перед записями 1 и 3 скрипт требует режим 1, перед записями 7 и 9 — режим 0. Иначе он ставит `$stopTx` и ничего больше не отправляет; в журнале строка `mode-gate-N`.

Фрагмент для `g4-8.ps1` (добавляется к скрипту G4-7):

```powershell
$hist = New-Object System.Collections.Generic.List[byte]
$script:mode = -1
function Track([byte[]]$buf) {
    $hist.AddRange($buf)
    if ($hist.Count -gt 4096) { $hist.RemoveRange(0, $hist.Count - 4096) }
    $a = $hist.ToArray()
    for ($i = 0; $i -le $a.Length - 7; $i++) {
        if ($a[$i] -eq 0xFA -and $a[$i+1] -eq 0x55 -and $a[$i+5] -eq 0x22) { $script:mode = ($a[$i+6] -shr 5) -band 3 }
    }
}
```

`Track $buf` вызывается в `Drain` после чтения. В запись плана добавляется поле `Mode` (1, 1, 0, 0 для записей 1, 3, 7, 9; иначе `-1`). Условие отправки: `Mode -eq -1 -or $script:mode -eq Mode`.

## Границы

Схема, скрипты и проверки повторяют [g4-7-windows-plan.md](g4-7-windows-plan.md) и цепочку за ним. Имена `g4-7` заменяй на `g4-8`.
Отличия:

1. `$plan` содержит 11 записей из таблицы, время `At` в миллисекундах, поле `Mode`.
2. Длительность цикла — 400 с; трасса — 840 с; пользователь наблюдает за Модулем 7 минут.
3. Порог перезапуска сессии до запуска скрипта — 300 с от старта трассы.
4. В порт пишутся ровно 11 массивов из таблицы. Автоповтора нет.
5. Перед каждой отправкой скрипт проверяет `g4-8-stop.flag`. Пользователь создаёт флаг при любой аномалии.
6. Ожидание скрипта — до 15 вызовов по 30 с. Ожидание tshark — `-Timeout 480`.
7. Если Модуль стартует в AM, записи 1 и 3 не уйдут (проверка режима). Агент фиксирует это и ждёт нового решения владельца.

## Критерии

| Вопрос | Результат |
|---|---|
| FM верхняя и нижняя границы | `0x22` с cid 0 «87.5» и cid 205 «108.0», либо прижатое значение, либо отказ |
| AM границы | cid 21 «711 KHz», cid 58 «1044 KHz» |
| Безопасность | нет переподключения, нет `0x28`, нет звуков |

Если все четыре кадра дали ожидаемый ответ, агент предлагает строку whitelist: FM cid 0–205, AM cid 21–58.
Если FM край вернул другое значение, диапазон FM в предложении берётся по измеренному ответу.
Если Модуль не ответил, граница не вносится.
