# План разделения UI и Core

Владелец утвердил [ADR 0010](../adr/0010-ui-core-separation.md) и [UI Contract](../architecture/ui-contract-spec.md) 26.11.2026 ([#321](https://github.com/krasotinpa/heterodyne-fm/issues/321)). Код сохраняет требования [requirements.md](../requirements.md). Контекст и исходные риски — в [аудите](../architecture/ui-core-audit.md).

```text
D → C → A → U → S → V ─┐
           A + S → T ─────┼→ I
              S → G ─────┘
```

Каждый этап реализации имеет свой PR. При общих файлах этапы выполняются последовательно. Перед переносом зависимости прочитайте её текущих потребителей и добавьте первый проверяемый тест для изменяемой границы. Любая реализация выполняет gate и review по [процессу проекта](../agents/codex-implementation.md).

## Управление зависимостями

1. D блокирует первый production PR. При закрытии D записать принятое решение, закрепить ссылку на применимую редакцию спецификации и пересмотреть метки.
2. C определяет файлы сборки. A завершает правила и перехват действий до U. U, S и V последовательно меняют Compose и его тесты.
3. После S выделить T только общий harness и адаптерные тестовые каталоги. V владеет визуальным набором и PNG. G владеет starter и документацией. Общий файл Gradle при необходимости меняет один этап по очереди.
4. I повторно проверяет быстрое отображение (до 200 мс, реакция на нажатие до 100 мс), бюджет звука и поведение на штатном ГУ. Результаты AVD и настоящего ГУ сохраняются отдельно.

План не закрывает имеющиеся задачи RTL-SDR, правки текста, тематизацию, импорт ZIP и аппаратную приёмку. Связи с ними перечислены в [аудите](../architecture/ui-core-audit.md). Для GitHub-карты применяются [правила трекера](../agents/issue-tracker.md) и [метки](../agents/triage-labels.md).
