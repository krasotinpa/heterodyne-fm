# Run 4: блок 5, жизненный цикл Fake Receiver

## Run 4 Preflight Report

База — `3ebd9fa43905c560a553a90b2c1d7f7325009a7e` после PR #314.
Изолированный AVD работает в WSL2 Ubuntu с API 30 x86_64, частным ADB 5038 и serial emulator-5580.
Отдельный preflight APK использует Fake Receiver и синтетический источник PCM 48 кГц через AudioTrack.
Паспорт и принадлежность AVD, процессов и дисков проверяются до установки.

```text
Паспорт → живой PCM → force-stop → обычный запуск → Stop → повторный launch → replug → ошибки
```

Проверки F1 и F2 используют обычные процессы. Инструментальная подготовка сохраняет 97,7 МГц и флаг воспроизведения.
Runner получает подтверждение PCM и автозапуска из журнала нового процесса.
Кнопка «Стоп» находится через дерево обычной Activity. Runner сверяет `lastPlayed=false` в сохранённом файле.
Каждый `force-stop` подтверждается исчезновением PID. После «Стоп» наблюдение длится 10 секунд.

В F3 первые восемь циклов ожидают однократный возврат потока на 97,7 МГц.
Два следующих цикла начинаются после «Стоп» и проверяют отсутствие нового PCM.
Сценарий сохраняет настоящий лимит автозапуска в 30 секунд и проверяет быстрый возврат отдельно.
Синтетические циклы переключают присутствие профиля в очереди адаптера. Они не подают Android USB broadcast и не открывают устройство.

## Defect and Issue Report

Новых продуктовых дефектов в синтетическом прогоне не найдено.
Сохранённая частота перед F2 — 97,7 МГц. После нового запуска Fake Receiver выдаёт собственную начальную частоту 90,3 МГц. Звук остаётся остановленным.
Вопрос показа последней сохранённой Станции относится к [#238](https://github.com/krasotinpa/heterodyne-fm/issues/238). Сценарий с новым синтетическим состоянием не заменяет проверку на ГУ.
